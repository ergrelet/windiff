# WinDiff analysis: Windows 10 1703 → 1709 core security surface (amd64)

## Scope

- Old: Windows 10 1703 / BASE / `10.0.15063.0 (WinBuild.160101.0800)`
- New: Windows 10 1709 / BASE / `10.0.16299.15 (WinBuild.160101.0800)`
- Architecture: amd64
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: exploit mitigations and audit telemetry, enclave completion, image notifications, DMA guard, CI/WDAC evolution, filesystem and win32k attack surface

## Executive summary

- **[EDR][anti-cheat][vuln-research] A large exploit-mitigation wave lands with audit state.** Windows 1709 adds ROP stack-pivot/caller/simulated-execution checks, export/import address filtering, child-process restriction, and module-tampering protection. `_EPROCESS` is reorganized into two explicit mitigation words with enforcing and audit bits.
- **[EDR][anti-cheat] Telemetry catches up with policy.** `EtwTiLogReadWriteVm` adds local/remote cross-process memory read/write visibility, while the new Security Mitigations provider logs enforced and audited dynamic-code, image-load, non-Microsoft-binary, child-process, and win32k restrictions.
- **[vuln-research][EDR] The enclave lifecycle becomes complete.** `NtCallEnclave` and `NtTerminateEnclave` join the earlier create/initialize/load services; `ntdll` gains loader/runtime APIs and `_EPROCESS` gains an enclave table, number, and lock.
- **[EDR][anti-cheat] Image-load monitoring gains `PsSetLoadImageNotifyRoutineEx`.** This is a new extended callback registration surface for defensive drivers. Its added capabilities and callback classes must be recovered from the prototype.
- **[EDR][vuln-research] CI/WDAC becomes refreshable and better instrumented.** `ci.dll` adds policy refresh/update, supplemental and AC-policy handling, runtime UMCI signing level, Smartlocker operational events, HVCI audit, and richer policy/signature telemetry.
- **[vuln-research] New filesystem and graphics paths remain important.** Extended directory query/change services add new filesystem buffer semantics; 43 win32k services add protected GPU sessions, flip objects, display management, and cursor/input configuration.

## New syscalls

### NT kernel

- **`NtCallEnclave`** [142] — enters or dispatches work into an enclave, with matching `ntdll` `Nt*`/`Zw*` stubs and `LdrCallEnclave`/`Rtl*EnclaveCall*` helpers. Impact: a new execution transition and exception/unwind boundary. **[vuln-research]** Confirm register/context sanitization, re-entry rules, exception dispatch, and target validation.
- **`NtTerminateEnclave`** [436] — tears down an enclave, again paired with user-mode stubs. The kernel adds software, hardware, and VSM enclave termination routines. Impact: teardown races, outstanding threads/modules, and page cleanup are high-value tests. **[vuln-research][EDR]**
- **`NtNotifyChangeDirectoryFileEx`** [271] — extends asynchronous directory-change notification. Paired `ntdll` stub: yes. `_IO_STACK_LOCATION::Parameters` gains `NotifyDirectoryEx`, confirming new I/O stack state. Impact: new information classes/record formats and cancellation/completion paths. **[EDR][vuln-research]**
- **`NtQueryDirectoryFileEx`** [312] — extends directory enumeration with a matching user stub. This is new filesystem parsing/serialization surface; review flags, restart semantics, record chaining, and short-buffer behavior. **[vuln-research]**

The kernel diff reports a fifth syscall named `?ScAnsiToUnicodeString@@YAJPEADPEAU_UNICODE_STRING@@@Z` [459]. That is a decorated C++ helper, has no `ntdll` stub, and is an extraction artifact. The apparent kernel-side removal of `NtWaitLowEventPair` is likewise not mirrored by `ntdll` and must not be treated as confirmed retirement. Thus, four new NT services are corroborated.

### win32k

Forty-three services are added and one is removed. High-signal clusters are:

- **Protected graphics sessions** — create/destroy/open/query/status services for `NtGdiDdDDI*ProtectedSession`, corroborated by stubs and `win32kbase` implementations. These introduce protected-content object lifetimes and NT-handle conversion. **[anti-cheat][vuln-research]** Audit authorization, cross-process handle duplication, status buffers, and teardown.
- **Flip, bundle, swap-chain, and display-manager objects** — four `NtFlipObject*` calls plus surface-to-swap-chain, bundle extraction/creation, display enumeration/operations, redirected/unordered present, and device-lost support. These expand complex GPU handle and array processing. **[vuln-research]**
- **DWM cursor/input-output configuration** — four `NtDWM*` services, `NtMITGetCursorUpdateHandle`, and `NtRIMEnableMonitorMappingForDevice` add cross-component cursor and device/display mapping state. **[anti-cheat][vuln-research]**
- Remaining `NtUser*` additions cover cursor objects/position, DPI discovery, resource brokering, waits, DC/window conversion, WOW cleanup, and inertia. Mostly functional, but all are kernel GUI entry points.

`NtGdiDdDDISetVidPnSourceOwner1` is the sole removed shadow-table service.

## New / changed security mitigations

### Two explicit `_EPROCESS` mitigation words

`_EPROCESS` replaces scattered fields with `MitigationFlags` and `MitigationFlags2`. The raw diff does not resolve these anonymous types automatically because the parent layout is reorganized, so the 1709 database was checked directly.

- **`MitigationFlagsValues`** adds or centralizes enforcement/audit state for CFG, ASLR/relocation, dynamic code, win32k disable/filtering, non-system fonts, remote and low-IL image maps, non-Microsoft binaries, loader integrity, and module tampering. Especially notable new facts are `AuditDisableDynamicCode`, `AuditDisallowWin32kSystemCalls`, `AuditFilteredWin32kAPIs`, `AuditProhibitRemoteImageMap`, `AuditProhibitLowILImageMap`, `AuditBlockNonMicrosoftBinaries`, `EnableModuleTamperingProtection`, and its no-inherit variant. **[EDR][anti-cheat]**
- **`MitigationFlags2Values`** is a new 32-bit word whose first 12 bits are enforce/audit pairs for Export Address Filter, EAF+, ROP stack-pivot detection, ROP caller checks, ROP simulated-execution checks, and Import Address Filter. These are strong anti-exploitation signals and also new compatibility/bypass targets. **[EDR][anti-cheat][vuln-research]**
- **`_PS_MITIGATION_OPTION`** adds `ROP_STACKPIVOT` [0x14], `ROP_CALLER_CHECK` [0x15], `ROP_SIMEXEC` [0x16], `EXPORT_ADDRESS_FILTER` [0x17], `EXPORT_ADDRESS_FILTER_PLUS` [0x18], `RESTRICT_CHILD_PROCESS_CREATION` [0x19], `IMPORT_ADDRESS_FILTER` [0x1a], and `MODULE_TAMPERING_PROTECTION` [0x1b]. This named policy list corroborates the runtime bits.
- **`_PS_MITIGATION_AUDIT_OPTIONS_MAP`** appears, while `PspInheritMitigationAuditOptions`, `PspReadIFEOMitigationAuditOptions`, and validation/system-map symbols show audit policy ingestion and inheritance. The data establishes audit plumbing, though not event enablement defaults.

The audit/enforce pairing lets defenders deploy policies in observation mode before enforcing them. Researchers should compare audit and enforce paths for semantic drift: an input accepted by audit but handled differently by enforcement can expose bypasses.

## New security-relevant features & components (beyond mitigations)

### Threat Intelligence and mitigation ETW

`EtwTiLogReadWriteVm` plus `THREATINT_READVM_*` and `THREATINT_WRITEVM_*` extends the 1703 TI provider to cross-process memory reads/writes, a core credential-theft and injection primitive. The separate Security Mitigations provider (`EtwSecurityMitigationsRegHandle`, `SecurityMitigationsProviderGuid`, and `EtwTimLog*`) records audit/enforce decisions for child-process creation, dynamic code, low-IL/remote image mapping, non-Microsoft binaries, and win32k calls. **[EDR][anti-cheat]** Confirm provider ACLs and schemas, correlate events with process start/image load, and test remote-versus-local classification.

### Extended image-load callback

`PsSetLoadImageNotifyRoutineEx` is a new kernel export. As an `Ex` form of a central defensive callback, it may add flags or notification classes, but the raw symbols do not establish which. **[EDR][anti-cheat]** Recover the prototype and compare callback registration limits, supported image types, removal semantics, and whether silo/enclave images are covered.

### Enclave loader and VSM integration

`ntdll` adds `LdrCreateEnclave`, `LdrInitializeEnclave`, `LdrLoadEnclaveModule`, `LdrCallEnclave`, `LdrDeleteEnclave`, runtime dispatch helpers, and enclave-specific load reasons. The kernel adds hardware/software/VSM enclave routines and `_EPROCESS::{EnclaveTable,EnclaveNumber,EnclaveLock}`. **[vuln-research][EDR]** This is a high-confidence completion of the protected-execution feature introduced in 1511.

### DMA Guard

`PiDmaGuardInitialize`, device-node pre-start/post-remove processing, policy/override state, PnP tracing, and `ClearDmaGuardProblem` appear. This is consistent with IOMMU-based device DMA policy enforcement. **[EDR][anti-cheat][vuln-research]** Confirm which buses/devices are gated, policy override trust, behavior without IOMMU support, and hot-plug/rollback handling.

### Code integrity / WDAC / Smartlocker

`ci.dll` adds policy refresh start/success/failure events, `CiUpdatePolicies`, supplemental/AC-policy parsing and signer registration, `CiSetRuntimeUmciSigningLevel`, Smartlocker operational telemetry, HVCI auditing, richer signature events, and platform/UEFI policy checks. **[EDR][vuln-research]** This indicates more dynamic policy lifecycle and visibility. Audit refresh atomicity, supplemental-policy binding, signer removal, persistent-variable updates, and runtime signing-level downgrade controls.

## New attack surface (routines, callbacks, object types)

- **Enclave call/termination** — execution and teardown transitions complete the state machine and should be fuzzed with concurrent module load, thread exit, and process termination. **[vuln-research]**
- **Extended directory query/notification** — new flags, record formats, and asynchronous completion/cancellation paths create filesystem attack surface. **[vuln-research][EDR]**
- **Protected GPU sessions and modern present/display objects** — protected-session handles, flip pools, bundles, swap chains, and display-manager operations add object graphs across win32k and display drivers. **[anti-cheat][vuln-research]**
- **`_KALPC_VIEW::u1::s1::SystemSpace`** — a new resolved bit marks an ALPC view as system-space. This reveals a new internal state distinction in an LPE-sensitive subsystem; determine which callers create such views and how mapping/access checks differ. **[vuln-research]**

## Notable structure changes

- `_EPROCESS` gains an enclave table, enclave number, enclave lock, and two mitigation words.
- `_IO_STACK_LOCATION::Parameters` gains `NotifyDirectoryEx`, pairing with the new notification syscall.
- `_FS_FILTER_PARAMETERS::QueryOpen` gains `CompletionStatus`, changing minifilter query-open completion state. Minifilter/EDR drivers should update private layout assumptions and test status propagation.
- `_DBGK_SILOSTATE` appears in `_ESERVERSILO_GLOBALS`, extending debugging state into server silos.

## Removed / deprecated

The only confirmed win32k syscall removal is `NtGdiDdDDISetVidPnSourceOwner1`. Several older hardware-protection exports disappear from `win32kfull.sys` while protected-session APIs appear in `win32kbase.sys`, consistent with interface relocation/replacement. The kernel-only `NtWaitLowEventPair` removal remains unconfirmed because the user stub persists.

## Extraction caveats

The decorated `ScAnsiToUnicodeString` entry is a clear syscall false positive. Many mitigation fields move from scattered `_EPROCESS` locations into anonymous words; the diff script therefore shows removals/additions at the parent rather than resolved bit-by-bit deltas. The report validated the referenced 1709 anonymous types directly. Large symbol counts in CI reflect real feature clusters mixed with compiler/static-library churn, so conclusions rely on coherent named routines and cross-binary companions.

## Research leads

1. Diff audit and enforce paths for every new mitigation, especially EAF/EAF+, ROP checks, IAF, and module tampering.
2. Validate TI and Security Mitigations ETW schemas, access controls, event loss, and behavior for protected/silo/enclave processes.
3. Recover and test the exact contract of `PsSetLoadImageNotifyRoutineEx`.
4. Fuzz enclave call/termination with concurrent faults, module operations, and process teardown.
5. Exercise WDAC policy refresh and supplemental-policy updates under interruption, stale caches, and signer revocation.
6. Audit protected GPU session handle conversion and extended directory record/cancellation paths.
