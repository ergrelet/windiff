# WinDiff analysis: Windows 10 core security surface — 21H1 → 21H2 (amd64)

## Scope

- Old: Windows 10 21H1 / BASE / `10.0.19041.928 (WinBuild.160101.0800)`
- New: Windows 10 21H2 / BASE / `10.0.19041.1288 (WinBuild.160101.0800)`
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: process component filtering, isolation state, and cryptographic validation

## Executive summary

- No syscall is added, removed, or renumbered. The security-relevant delta is small and internal, consistent with another release on the 19041 servicing baseline.
- **[EDR] [anti-cheat] [vuln-research]** A coherent process component-filter mechanism appears: new process-creation attribute `PsAttributeComponentFilter`, `_EPROCESS::DisabledComponentFlags`, exported `PsIsComponentEnabled`, and internal `PspApplyComponentFilterOptions`.
- **[vuln-research]** Server silos gain explicit time-zone virtualization state and per-silo bias data. This improves isolation fidelity; its security value is preventing host/container state leakage or inconsistent policy decisions rather than adding a direct mitigation.
- **[EDR] [vuln-research]** CI and CNG both add elliptic-curve/Montgomery public-key validation helpers, while CNG adds safe-prime group construction and validation machinery. This cross-binary pairing indicates strengthened or generalized key validation.
- **[anti-cheat] [vuln-research]** `MmUpdateUserShadowStackValue` shows continuing CET maintenance, but there are no new CET policy bits in this transition; it should be read as implementation refinement after 21H1.

## New / changed security mitigations

No new resolved mitigation bitfield appears. The primary policy addition is component filtering:

- **`_PS_ATTRIBUTE_NUM::PsAttributeComponentFilter [0x1d]`**, **`_EPROCESS::DisabledComponentFlags [0xa20]`**, **`PsIsComponentEnabled`**, and **`PspApplyComponentFilterOptions`** form a complete process-creation-to-runtime feature gate. **Fact:** all four names/layout changes are present. **Inference:** a creator can select OS components unavailable to the child, likely for reduced-capability process environments or compatibility isolation. **[EDR] [anti-cheat] [vuln-research]** Reverse the accepted mask, privilege/caller rules, and whether disabling a component actually removes reachable handlers or only changes behavior.
- **`PsAttributeMachineType [0x1c]`** also appears. It likely accompanies cross-architecture process creation or emulation selection, but that purpose is not established by the type name alone. **[vuln-research]**

## New security-relevant features & components (beyond mitigations)

### Process and component isolation

The component-filter pairing is the highest-value change. It potentially shrinks process-visible functionality and therefore attack surface, while also creating policy parsing and inheritance rules that can be bypassed. `PspDeleteProtectedProcessParameters` appears in the same kernel delta, but the data does not show that it is part of component filtering; keep those findings separate until call graphs prove a link.

### Server-silo virtualization

`_ESERVERSILO_GLOBALS` gains `TzVirtualizationSupported` and `ExTimeZoneState`; `_SILO_USER_SHARED_DATA` gains time-zone ID, bias stamp, bias, and effective start/end fields. Kernel routines initialize, persist, and clean up silo time-zone state, and ntdll exports `RtlGetSystemTimeAndBias`. **[vuln-research]** This is a coherent container-isolation feature. Test namespace transitions, host time-zone updates, and teardown for stale pointer/state leakage.

### Cryptographic and trust validation

- `SymCryptEckeyPerformPublicKeyValidation`, `SymCryptEcpointScalarMul`, and `SymCryptMontgomeryIsEqual` appear in both CI and CNG. CNG additionally gains point-on-curve/zero/equality checks and integer/modulus primitives. **[EDR] [vuln-research]** This strongly suggests more explicit validation of public key material before trust decisions. Confirm callers and rejection behavior for invalid-curve and non-canonical points.
- CNG adds named safe-prime group setup and `BCryptFlagsToSymCryptKeyValidationFlags`, indicating validation policy is propagated from BCrypt API flags. **[vuln-research]** Differential-test group parameters and flag combinations.
- CI includes a new `MicrosoftIdentityRoot2020` public-key object. **Fact:** the symbol exists. **Inference:** CI's trust material was updated for a newer Microsoft identity root. Validate its actual certificate/key use before asserting a trust-chain change.

### CET maintenance

`MmUpdateUserShadowStackValue` is a new kernel routine while `PspFreeUserFiberShadowStackInternal` disappears. This looks like a refactoring or lifecycle refinement for user shadow stacks. **[anti-cheat] [vuln-research]** Trace fiber and thread teardown paths; the diff alone does not show changed policy.

## New attack surface (routines, callbacks, object types)

- There are **no new syscalls**.
- **`PsIsComponentEnabled`** is a new kernel export. Driver callers can query per-process component state; the security risk lies in confused-deputy behavior if kernel components fail to enforce the same filter consistently. **[EDR] [anti-cheat] [vuln-research]**
- **`DxgkEngNotifyDisplayChange`** is a new `win32kbase.sys` export imported by `win32kfull.sys`. It is driver/internal display notification surface, not a user syscall. **[vuln-research]** Review callback lifetime and session ownership.

## Notable structure changes

- `_EPROCESS` gains `DisabledComponentFlags` at `0xa20` without a broad layout rewrite, strengthening the case that component filtering is a focused addition.
- `_PCI_BUSMASTER_RID_TYPE` adds an explicit invalid value and shifts existing enum values. Debugger, telemetry, and driver code must not assume the previous zero-based meanings.
- `_IO_COMPLETION_CONTEXT` in win32k gains a 64-bit `UsageCount`, consistent with explicit lifetime accounting. This is a patch-diff lead for completion-context races, not a new exposed API.

## Removed / deprecated

No syscall or security export is removed. Most symbol removals are feature-state or implementation churn. The removal of the user-fiber shadow-stack free helper should be traced to its replacement before drawing a lifecycle conclusion.

## Research leads

1. Recover the component-filter mask and map every bit to the gated subsystem; test inheritance and mutation across process creation.
2. Search for kernel consumers that ignore `PsIsComponentEnabled`, creating inconsistent filtering or confused-deputy paths.
3. Exercise silo time-zone changes during process creation and teardown to find cross-silo state leakage.
4. Feed malformed EC points, safe-prime parameters, and flag combinations through the callers of the new SymCrypt validation helpers.
5. Trace `MmUpdateUserShadowStackValue` around fiber conversion, exception dispatch, and process teardown.
