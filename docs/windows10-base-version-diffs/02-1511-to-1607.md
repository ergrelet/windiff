# WinDiff analysis: Windows 10 1511 → 1607 core security surface (amd64)

## Scope

- Old: Windows 10 1511 / BASE / `10.0.10586.0 (th2_release.151029-1700)`
- New: Windows 10 1607 / BASE / `10.0.14393.0 (rs1_release.160715-1616)`
- Architecture: amd64
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: signing and policy interfaces, process hardening, container isolation, win32k attack surface, and code-integrity enforcement

## Executive summary

- **[EDR][vuln-research] Signing and security policy gain native interfaces.** `NtQuerySecurityPolicy` and `NtSetCachedSigningLevel2` have matching `ntdll` stubs; the latter is a versioned expansion of cached signing metadata. `ci.dll` simultaneously gains richer system-integrity policy parsing, WHQL enforcement/auditing, weak-crypto policy, and silo-aware state.
- **[vuln-research] Registry transactions become directly exposed.** Create/open/commit/rollback registry-transaction syscalls form a coherent new state machine. This adds useful atomicity but also new lifetime, rollback, access-check, and namespace interactions.
- **[anti-cheat][EDR] Process and PPL hardening advances.** `_EPROCESS` gains `DisableDynamicCodeAllowOptOut` and `AutomaticallyOverrideChildProcessPolicy`; `_PS_PROTECTED_SIGNER` gains `PsProtectedSignerWinSystem`.
- **[vuln-research][anti-cheat] win32k replaces broad composition surface with batching and adds interactive-control input.** Thirty-one shadow-table services arrive while 28 disappear. `NtDCompositionProcessChannelBatchBuffer` consolidates many former per-operation calls into a complex batch parser, and a new interactive-control/haptics family expands input handling.
- **[EDR][vuln-research] Server silos become a kernel-wide framework.** Stable context-slot, monitor, object-directory, ETW, WNF, Security Reference Monitor, CI, and registry participation replace the earlier ad-hoc silo object APIs.

## New syscalls

### NT kernel

- **`NtCreateRegistryTransaction`** [178], **`NtOpenRegistryTransaction`** [282], **`NtCommitRegistryTransaction`** [147], and **`NtRollbackRegistryTransaction`** [364] — create a complete user-reachable registry transaction lifecycle, with matching `ntdll` stubs. The Configuration Manager ownership is explicit in kernel symbols such as `CmRegistryTransactionType`. Impact: new handle/state transitions and rollback paths; test cross-silo namespaces, privilege changes between create and commit, and cancellation races. **[vuln-research]**
- **`NtQuerySecurityPolicy`** [329] — exposes a security-policy query with a matching user stub. The exact policy classes are absent from the diff, so reachability and sensitivity must be determined from the handler. **[EDR][anti-cheat][vuln-research]**
- **`NtSetCachedSigningLevel2`** [375] — a versioned signing-cache setter with a matching user stub. The `2` suffix strongly implies additional metadata or flags beyond `NtSetCachedSigningLevel`; it should be treated as a code-integrity boundary, not a cosmetic wrapper. **[EDR][vuln-research]** Confirm accepted callers, file-handle validation, catalog association, and downgrade behavior.

`ntoskrnl.exe` also reports `CmpForceInvalidatePreCallback` [325] as a syscall. It is an internal `Cmp*` name, has no `ntdll` stub, and is therefore treated as a syscall-extraction false positive. The kernel reports removal of `NtQueryPortInformationProcess`, but `ntdll` does not remove its stub; verify the service table/disassembly before concluding that the handler was retired.

### win32k

The most important additions among 31 new services are:

- **`NtDCompositionProcessChannelBatchBuffer`** [4413] — a batch interpreter replacing many removed `NtDComposition*` operations. Batching reduces syscall count but concentrates a larger command grammar behind one entry point, making length, opcode, object-reference, and rollback validation prime fuzzing targets. **[vuln-research]**
- **Interactive-control family** — `NtUserAcquireInteractiveControlBackgroundAccess`, `NtUserGetInteractiveControlDeviceInfo`, `NtUserGetInteractiveControlInfo`, `NtUserInteractiveControlQueryUsage`, `NtUserSendInteractiveControlHapticsReport`, and `NtUserSetInteractiveControlFocus` expose HID-like device discovery, focus, background access, and output reports. Impact: new device/report parsing and input-ownership transitions. **[anti-cheat][vuln-research]**
- **`NtGdiCreateOPMProtectedOutput`** [4468] — creates an Output Protection Manager object. This is likely DRM/protected-display functionality; handle ownership, certificate negotiation, and object teardown are security-sensitive. **[vuln-research][anti-cheat]**
- **Per-monitor DPI services** — context-based getters/setters and `NtUserSystemParametersInfoForDpi` replace older process-wide DPI calls. They are mainly functional but add window-tree state transitions in a historically vulnerable subsystem. **[vuln-research]**
- New D3DKMT overlay, FSE-block, commitment, allocation-property, HDR-metadata, and direct-flip calls broaden GPU/display state management. Review variable-sized adapter and allocation arrays even where the feature itself is not security-focused.

Twenty-eight removed services include numerous fine-grained DirectComposition resource operations, older process-DPI APIs, and queue/token-manager calls. Their replacement with batching and context APIs represents attack-surface migration, not a simple net reduction.

## New / changed security mitigations

- **`_EPROCESS::Flags3::DisableDynamicCodeAllowOptOut`** (bit 14) and **`_ETHREAD::DisableDynamicCodeOptOut`** (bit 18) — directly show per-process policy plus per-thread opt-out state for dynamic-code prohibition. This suggests controlled exceptions to ACG-style policy. Exceptions can be operationally necessary, but the authorization/inheritance rules are a bypass target. **[EDR][anti-cheat][vuln-research]**
- **`_EPROCESS::Flags3::AutomaticallyOverrideChildProcessPolicy`** (bit 19) — adds kernel state for overriding inherited child-process restrictions. Its name is explicit; the data does not show which trusted creators may set it. **[EDR][anti-cheat][vuln-research]**
- **`_PS_PROTECTED_SIGNER::PsProtectedSignerWinSystem`** [7] — introduces a new Protected Process Light signer category. This expands the protection lattice and can affect which processes or drivers may open privileged handles. **[EDR][anti-cheat]** Confirm signing-level comparisons and allowed-access matrices in `Psp*Protection` and `Se*Signing` paths.
- **`_MI_FLAGS::SlatKernelCodeProtected`** and repositioned `ProtectedPagesEnabled` — indicate second-level address translation participation in kernel code protection. This is consistent with VBS/HVCI hardening, corroborated by `VslValidateDynamicCodePages` and nested-page-protection symbols. **[EDR][anti-cheat][vuln-research]**

The resolved anonymous-member changes contain WHEA, PFN, and disk-I/O attribution changes, not hidden mitigation flags. The mitigation claims above come from named fields and enums.

## New security-relevant features & components (beyond mitigations)

### Code integrity, WHQL, and policy

`ci.dll` adds `CiAuditDriverLoadSignature`, `CiGetInstrumentSignatureInformation`, `CiLogSIPolicyEvent2`, `CipWhqlEnforcementEnabled`, `CipDeserializeWeakCryptoPolicies`, SI-policy signer/file-rule parsers, and HVCI interface state. `NtSetCachedSigningLevel2` and `NtQuerySecurityPolicy` provide companion native interfaces. Taken together, this is a broad signing-policy and observability expansion, including weak-cryptography decisions and driver-signature audits. **[EDR][vuln-research]** Reverse the cached-signing setter alongside CI's catalog and policy consumers; validate whether failed or stale cache entries can weaken enforcement.

### Server-silo framework

The kernel adds `PsAllocSiloContextSlot`, `PsCreateSiloContext`, `PsRegisterSiloMonitor`, `PsStartSiloMonitor`, permanent-context APIs, and host/effective-silo queries. New `_ESERVERSILO_GLOBALS`, `_SEP_SILOSTATE`, `_WNF_SILODRIVERSTATE`, and silo-aware ETW state show that registry, security, WNF, ETW, object namespaces, and CI now share a lifecycle. `ci.dll` itself registers a silo monitor. **[EDR][anti-cheat][vuln-research]** This should improve isolation consistency, but teardown order and stale per-silo policy/cache state deserve targeted testing.

### Pico-process support

New `PspCreatePicoProcess`, `PspCreatePicoThread`, and per-process/thread `PicoContext` paths reveal a lightweight process model integrated with silos. The raw names establish the component, not its intended consumer. Alternative process creation and notification semantics matter to EDR coverage and anti-cheat assumptions. **[EDR][anti-cheat]** Confirm whether all process/thread/image callbacks observe pico objects and what token/handle semantics differ.

## New attack surface (routines, callbacks, object types)

- **Transactional registry object** — the four native services create a new object lifetime spanning namespace, security descriptor, and rollback logic. **[vuln-research]**
- **DirectComposition batch parser** — consolidation into `NtDCompositionProcessChannelBatchBuffer` creates a high-value structured-input fuzz target in win32k. **[vuln-research]**
- **Interactive-control manager** — extensive device parsing, report generation, background access, haptics, focus, and I/O-control routines appear in `win32kfull.sys`. Integrity checks and window ownership should be audited. **[anti-cheat][vuln-research]**
- **`NtSetCachedSigningLevel2`** — new file/signing metadata crosses a trust boundary and can influence later image validation. **[EDR][vuln-research]**

## Notable structure changes

- `_EJOB` gains `ParentSilo`, `ServerSiloGlobals`, a `Silo` bit, and hard-reference accounting, reflecting explicit silo hierarchy and lifetime.
- `_ETW_GUID_ENTRY`, `_ETW_REALTIME_CONSUMER`, and `_WMI_LOGGER_CONTEXT` become silo-aware; defenders should not assume global-only logger/provider state.
- `_WORK_QUEUE_ENTRY::Parameters::{Read,AsyncRead}` gains `DiskIoAttribution`, and async reads gain `IoIssuerThread`. This is accounting/attribution evidence, potentially useful to telemetry consumers, but it is not itself a callback API.

## Removed / deprecated

The old monitor-context server-silo API family is removed and replaced by context-slot/monitor primitives. `NtQueryPortInformationProcess` appears removed only on the kernel side and needs validation. win32k retires many individual DirectComposition calls and older DPI calls in favor of batch/context interfaces.

## Research leads

1. Recover the `NtSetCachedSigningLevel2` structure and compare access checks and cache invalidation with version 1.
2. Fuzz transaction create/open/commit/rollback sequences across duplicated handles, registry namespaces, and silo teardown.
3. Build a grammar-aware fuzzer for `NtDCompositionProcessChannelBatchBuffer`, including failed-command rollback.
4. Map `PsProtectedSignerWinSystem` into PPL handle-access decisions and signing-level comparisons.
5. Test callback and telemetry coverage for pico processes and processes inside nested/terminating silos.

## Extraction caveats

The `CmpForceInvalidatePreCallback` syscall row is not corroborated and is almost certainly a parser artifact. Large module churn in several PDBs and widespread win32k forwarding changes inflate raw symbol/export movement; the report relies on paired syscalls, exports, named types, and coherent symbol clusters rather than treating every new symbol as new behavior.
