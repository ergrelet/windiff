# WinDiff analysis: Windows 10 1607 → 1703 core security surface (amd64)

## Scope

- Old: Windows 10 1607 / BASE / `10.0.14393.0 (rs1_release.160715-1616)`
- New: Windows 10 1703 / BASE / `10.0.15063.0 (WinBuild.160101.0800)`
- Architecture: amd64
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: threat-intelligence telemetry, process mitigations, hot patching, code integrity, and win32k/GPU/input attack surface

## Executive summary

- **[EDR][anti-cheat] The kernel Threat Intelligence provider appears.** `EtwTiLogAllocExecVm`, `EtwTiLogMapExecView`, `EtwTiLogProtectExecVm`, `EtwTiLogQueueApcThread`, and `EtwTiLogSetContextThread`, together with local/remote event constants and `ThreatIntProviderGuid`, add high-value visibility into common injection and executable-memory primitives.
- **[EDR][anti-cheat][vuln-research] Process mitigations become more explicit and stricter.** `_EPROCESS` gains dynamic-code remote-downgrade control, loader integrity continuity (enforce and audit), CFG export suppression, and strict CFG state. Matching `ntdll` loader routines corroborate the loader-integrity and signing story.
- **[vuln-research] Native hot-patch loading becomes a syscall.** `NtLoadHotPatch` is paired with `Mi*` preparation/application and `VslApplyHotPatch` secure-kernel paths. It is probably privileged, but it still adds a complex image/relocation/state transition worth auditing.
- **[vuln-research][anti-cheat] win32k undergoes a major surface migration.** Seventy-three services are added and 77 removed. New GPU hardware queues/contexts, raw-input management, input synthesis, mouse interception, and HID injection replace many legacy DirectDraw/video-port calls.
- **[EDR][vuln-research] CI policy becomes application-aware.** `ci.dll` exports `CiSetTrustedOriginClaimId` and adds per-app SI-policy/Smartlocker logic, image revalidation, and trusted-origin claim handling.

## New syscalls

### NT kernel

- **`NtLoadHotPatch`** [254] — introduces a native hot-patch loading path, with a matching `ntdll` stub. Kernel additions (`MiPrepareImageForHotPatch`, `MiApplyDriverHotPatch`, `RtlFindHotPatchInformation`) and `VslApplyHotPatch` confirm image preparation plus VBS participation. Impact: a new parser/relocation/update path that can modify executing code; verify privilege checks, signer requirements, rollback, and race handling. **[EDR][vuln-research]**
- **`NtCompareSigningLevels`** [152] — compares code-signing levels and has a matching user stub. Its security value depends on whether callers can use comparison results only or influence policy decisions elsewhere. **[EDR][anti-cheat][vuln-research]** Confirm operand capture and the relationship to `CiSetTrustedOriginClaimId` and process protection checks.
- **`NtQueryInformationByName`** [315] — adds a name-based I/O query, paired with kernel `IoQueryInformationByName` and an `ntdll` stub. Name resolution plus variable information classes can create path-normalization, reparse, namespace, and buffer-validation risk. **[vuln-research]**
- **`NtAcquireProcessActivityReference`** [103] — creates or acquires a process activity-reference object (`PspActivityReferenceObjectType`). It likely coordinates process lifetime or power/activity accounting. Security impact is mainly handle/lifetime correctness and denial-of-service potential. **[vuln-research]**
- **`NtConvertBetweenAuxiliaryCounterAndPerformanceCounter`** [157] and **`NtQueryAuxiliaryCounterFrequency`** [306] — expose timing-counter conversion/frequency data. These appear functional, but precise clocks can affect side-channel research and conversion arithmetic should be checked for overflow. **[vuln-research]**

All six have matching `ntdll` stubs. The 336 kernel and 347 `ntdll` renumberings reflect table regeneration, not additional features.

### win32k

Rather than repeat all 73 names, the additions form three security-relevant clusters:

- **Raw Input Manager and MIT input stack** — 15 `NtRIM*` services manage device I/O, buffers, registration, properties, PnP/timer events, and test mode; 14 `NtMIT*` services manage input processing, callbacks, mouse interception, synthesis, and core messaging. `NtUserInitializeGenericHidInjection`, `NtUserInitializePointerDeviceInjectionEx`, and `NtUserInjectGenericHidInput` add explicit HID injection. This is a large new input trust boundary. **[anti-cheat][vuln-research]** Validate desktop/session ownership, integrity checks, injected-versus-hardware provenance, callback lifetime, test-mode authorization, and HID report lengths.
- **GPU hardware contexts and queues** — create/destroy/submit/wait/signal services for hardware queues and contexts, plus allocation priority, budget target, process scheduling band, and yield controls. User-supplied arrays, synchronization objects, and allocation handles make these high-value driver/kernel fuzz targets. **[vuln-research][anti-cheat]**
- **DPI/composition/layout** — DirectComposition synchronization/shared visual calls and new DPI/layout controls add functional state. They are lower signal individually, but remain reachable in a historically important LPE subsystem.

The removal of 77 services is dominated by legacy `NtGdiDd*` DirectDraw/D3D/video-port interfaces. This shrinks obsolete surface while simultaneously adding modern queue/input paths; the meaningful conclusion is replacement, not a four-call net reduction.

## New / changed security mitigations

- **`_EPROCESS::Flags3::DisableDynamicCodeAllowRemoteDowngrade`** (bit 23) — explicitly controls remote downgrade of a process's dynamic-code policy. This closes a policy-relaxation path unless authorized. **[EDR][anti-cheat][vuln-research]** Confirm what constitutes a remote caller and which access rights permit downgrade.
- **`_EPROCESS::Flags3::LoaderIntegrityContinuityEnabled`** (bit 24) and **`LoaderIntegrityContinuityAudit`** (bit 25) — add enforce/audit state for continuous loader integrity. `ntdll` adds `LdrpEnforceIntegrityContinuity`, `LdrpAuditIntegrityContinuity`, validation, telemetry, and module signing-level state. The cross-binary pairing makes this a high-confidence mitigation addition. **[EDR][anti-cheat]**
- **`_EPROCESS::Flags3::ControlFlowGuardExportSuppressionEnabled`** (bit 26) and **`ControlFlowGuardStrict`** (bit 29) — record stronger CFG modes. `ntdll` adds `LdrControlFlowGuardEnforcedWithExportSuppression`, corroborating loader participation. Export suppression limits valid targets; strict mode likely rejects modules lacking acceptable CFG metadata. **[EDR][anti-cheat][vuln-research]** Confirm exact module compatibility and fallback rules.
- **`_MI_FLAGS::SecureKernelCfgEnabled`** (bit 19) and `_MMPTE_HARDWARE::WsleProtection` — show memory-manager/VBS participation in code-flow and working-set protection. **[all]** Their enforcement behavior needs secure-kernel and PTE-write path analysis.
- A new `_PS_MITIGATION_OPTION` enum names existing policies plus `RETURN_FLOW_GUARD`, `LOADER_INTEGRITY_CONTINUITY`, `STRICT_CONTROL_FLOW_GUARD`, and `RESTRICT_SET_THREAD_CONTEXT`. Because the entire type is new to extracted symbols, type appearance alone cannot date every enumerated policy; the new `_EPROCESS` fields above provide the reliable per-version evidence.

## New security-relevant features & components (beyond mitigations)

### Threat Intelligence ETW

The new provider records executable allocation, executable section mapping, executable protection changes, user APC queuing, and thread-context setting, with explicit local/remote variants. These operations form common process-injection chains. **[EDR][anti-cheat]** This is a substantial visibility gain: products can correlate memory creation/protection with APC/context manipulation instead of relying only on user-mode hooks. Confirm provider enablement/access controls, event schemas, dropped-event behavior, and whether kernel callers are covered.

### Code integrity and trusted origin

`CiSetTrustedOriginClaimId` becomes the ninth CI export. Private additions include per-app rule matching, Smartlocker EA plus process-token checks, SI-policy V3 parsing, image revalidation, trusted-origin claims, and policy promotion. **[EDR][vuln-research]** This appears to bind application identity/provenance more closely to code execution decisions. Reverse who may set a trusted-origin claim and whether claims survive file replacement, token changes, or cache reuse.

### Hot patching under VBS

The native syscall, memory-manager routines, and `VslApplyHotPatch`/nested-page protection form a companion chain across the NT kernel and virtualization layer. **[EDR][vuln-research]** This suggests secure-kernel coordination rather than writable-code patching alone. Audit signature verification, patch extent calculation, page permission transitions, and failure rollback.

### Server-silo telemetry and impersonation

`_EJOB` gains `ContainerTelemetryId`, user-mode silo thread-impersonation controls, and system-root state; ETW gains per-silo tracing blocks. These facts show improved attribution and explicit control over silo impersonation. **[EDR][vuln-research]** Confirm whether events retain both host and container identities and test impersonation during silo shutdown.

## New attack surface (routines, callbacks, object types)

- **Input interception and injection** — `NtMITSetInputCallbacks`, `NtMITEnableMouseIntercept`, synthesis calls, `NtRIMDeviceIoControl`, and generic HID injection expose complex asynchronous state to user mode. **[anti-cheat][vuln-research]**
- **GPU hardware queues** — command submission and sync-object arrays bridge win32k and display miniport drivers. **[vuln-research]**
- **Hot-patch loader** — image parsing and live code mutation are high-impact even behind strong privilege checks. **[EDR][vuln-research]**
- **`NtQueryInformationByName`** — name parsing plus information dispatch creates a compact, fuzzable kernel I/O surface. **[vuln-research]**

## Notable structure changes

- `_LDR_DATA_TABLE_ENTRY` gains `SigningLevel`, pairing user-mode loader state with CI/mitigation enforcement.
- `_EJOB` gains a container telemetry GUID and silo impersonation enable/disable bits.
- `_ETW_WMITRACE_WORK` gains `SiloSessionId`, and new `_ETW_SILO_TRACING_BLOCK` state reinforces per-container attribution.
- `_SEGMENT::u1` replaces a raw creating-process pointer with `CreatingProcessId`, plausibly reducing pointer lifetime coupling; that security interpretation should be verified from consumers.

## Removed / deprecated

Most noteworthy is the removal of dozens of legacy DirectDraw/D3D/video-port win32k services. The raw table still gains large modern input and GPU interfaces, so this is attack-surface modernization rather than simple contraction. LowBox handle-table types are replaced by cached-handle state in `_TOKEN`; audit code that assumed the old internal layout.

## Extraction caveats

`win32k.sys` reports +1,134 exports, while companion binaries also show hundreds of export moves. This is consistent with a forwarding/stub visibility or architectural attribution change around the split win32k components, not 1,134 wholly new callable behaviors. The report prioritizes shadow-table syscalls and coherent implementations. The CNG diff (+445/-500 symbols) also contains major library/build churn; only explicit FIPS-generation routines are treated as a modest cryptographic implementation change, not an algorithmic redesign.

## Research leads

1. Validate and consume the five new Threat Intelligence event families; measure gaps under kernel-originated and protected-process operations.
2. Reverse `NtLoadHotPatch` through `MiApplyDriverHotPatch` and `VslApplyHotPatch`, then fuzz signed-but-malformed metadata in a lab.
3. Trace all writes and policy setters for the four new `_EPROCESS::Flags3` mitigation bits.
4. Fuzz `NtRIM*`, `NtMIT*`, HID injection, and hardware-queue services with a session/desktop-aware harness.
5. Determine authorization and cache-lifetime rules for `CiSetTrustedOriginClaimId`.
