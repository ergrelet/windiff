# WinDiff analysis: Windows 10 core security surface — 1909 → 2004 (amd64)

## Scope

- Old: Windows 10 1909 / BASE / `10.0.18362.418 (WinBuild.160101.0800)`
- New: Windows 10 2004 / BASE / `10.0.19041.264 (WinBuild.160101.0800)`
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: new syscall and GUI attack surface, CET and virtualization hardening, code integrity, and defensive telemetry

## Executive summary

- **[vuln-research]** This is a full platform transition, not an enablement-package delta: the kernel adds eight reported services and win32k adds 64 GUI/compositor/DXG/input services. Six kernel additions have matching new ntdll stubs; the win32k additions have matching `__win32kstub_*` exports.
- **[EDR] [anti-cheat] [vuln-research]** User-mode CET becomes an explicit process policy. The data shows new audit and instruction-pointer-validation bits in `_EPROCESS`, a new mitigation option, a CET capability word in shared user data, and kernel routines that validate CET context state.
- **[vuln-research] [anti-cheat]** Cross-VM synchronization becomes a coherent kernel object family: new event/mutant object types, create/acquire services, object-manager lifecycle routines, and cross-VM WNF/extension-host support.
- **[EDR] [anti-cheat]** IOMMU/DMA-remapping and DMA Guard logic expands dramatically, including device domains, fault reporting, security policy, and `HalpIommuInitializeDmaGuardPolicy`. This is strong evidence of a broader hardware-backed device-isolation implementation.
- **[EDR] [vuln-research]** `ci.dll` adds HVCI compliance checking, incompatibility publication, CI black-box diagnostics, and transactional policy deployment. The names establish a materially expanded CI/HVCI enforcement and diagnostic path, although exact policy semantics require reversing.

## New syscalls

The raw data reports 347 kernel and 1,193 win32k renumberings. Those are table-rebuild artifacts relevant to direct-syscall tooling, not new features.

### NT kernel

- **`NtAcquireCrossVmMutant` [103]** — new cross-VM synchronization operation. A matching ntdll `Nt`/`Zw` export exists. Combined with `ExCrossVmMutantObjectType` and `ExpAcquireCrossVmMutant`, this is a genuine user-to-kernel object surface. **[vuln-research]** Confirm by reversing validation of object names, handles, and VM/host identity.
- **`NtCreateCrossVmMutant` [164]** and **`NtCreateCrossVmEvent` [163]** — constructors for cross-VM synchronization objects. The mutant has a matching ntdll stub; this dataset does not show a new ntdll stub for the event, although the kernel exports `NtCreateCrossVmEvent`/`ZwCreateCrossVmEvent`. **[vuln-research] [anti-cheat]** The security boundary is the interesting part: object namespace, access checks, and host/guest routing deserve review.
- **`NtAllocateUserPhysicalPagesEx` [116]** — extended physical-page allocation with a matching ntdll stub. It likely adds policy or placement controls to an already sensitive memory primitive. **[vuln-research]** Compare parameters and privilege checks with `NtAllocateUserPhysicalPages`.
- **`NtContinueEx` [161]** — extended context continuation, paired in ntdll. It arrives alongside `_KCONTINUE_TYPE` and CET context-validation work, so a CET-aware continuation path is plausible but not proven from names alone. **[EDR] [vuln-research]** Reverse the handler and its continuation-type cases.
- **`NtPssCaptureVaSpaceBulk` [316]** — bulk process-snapshot virtual-address capture, paired in ntdll. This expands introspection/capture surface over another process's address space. **[EDR] [vuln-research]** Check handle rights, snapshot lifetime, and buffer arithmetic.
- **`NtLoadKey3` [470]** — a third-generation registry-hive loading interface with a matching stub. Hive parsing and load policy are privileged but historically valuable attack surface. **[EDR] [vuln-research]** Diff its parameter structure and authorization path against `NtLoadKey2`.
- **`NtWaitLowEventPair` [469]** — a new low-level synchronization service with no new ntdll stub in this diff. Treat reachability as unresolved until its caller and export path are identified. **[vuln-research]**

The kernel diff also reports removal of `NtFlushWriteBuffer` plus one malformed symbol-like syscall entry. Because the latter is clearly extraction noise and the former lacks a companion ntdll removal, do not infer that the public API disappeared without checking the service table and disassembly.

### win32k

Sixty-four services are added and six removed. The highest-signal clusters are:

- **DXG/display handles and resource pinning** — `NtDxgkDuplicateHandle`, `NtDxgkEnumAdapters3`, `NtDxgkPinResources`, `NtDxgkUnpinResources`, and `NtDxgkDisplayPortOperation`. These add handle, adapter-enumeration, and memory-lifetime paths at the graphics boundary. **[vuln-research]** Audit object ownership, integer sizes, and pin/unpin cleanup.
- **MIT/minuser input routing** — 17 `NtMIT*` services plus `NtMinGetInputTransform`, `NtMinInteropCoreMessagingWithInput`, and three `NtMinQ*` queue operations. The names show a new message/input routing plane spanning pointer capture, foreground routing, observation state, and cross-process posting. **[anti-cheat] [vuln-research]** This is relevant to synthetic-input attribution and GUI sandbox escapes.
- **Moderncore composition** — 16 `NtModerncore*` services for DComposition/GDI HWND targets, navigation visuals, resize synchronization, and a process connection. **[vuln-research]** The process-connect and resource-lifetime handlers should be fuzzed as a group.
- **User/input state** — new raw-mouse, keyboard-posting, input-service, shared-window-data, pointer-device-space, and activation-group calls. **[anti-cheat] [vuln-research]** Validate whether callers are restricted to trusted input services and whether shared data is copied safely.

## New / changed security mitigations

- **`_EPROCESS::MitigationFlags2Values`** — the resolved anonymous bitfield gains `AuditCetUserShadowStacks`, `AuditCetUserShadowStacksLogged`, `UserCetSetContextIpValidation`, `AuditUserCetSetContextIpValidation`, and `AuditUserCetSetContextIpValidationLogged`, each one bit. This is direct evidence of CET shadow-stack auditing and set-context IP validation state. **[EDR] [anti-cheat] [vuln-research]**
- **`_PS_MITIGATION_OPTION_USER_CET_SET_CONTEXT_IP_VALIDATION` [0x20]** — a new mitigation selector, while `_PS_MITIGATION_OPTIONS_MAP` and `_PS_MITIGATION_AUDIT_OPTIONS_MAP` grow from two to three 64-bit words. The matching `KeVerifyContextIpForUserCet`, `KiVerifyContextIpForUserCet`, and CET audit loggers support the interpretation that this is a surfaced process policy, not spare-bit churn. **[all]**
- **`_KUSER_SHARED_DATA::UserCetAvailableEnvironments` [0x30c]** replaces `SystemCallPad0`. This exposes CET environment capability state to user mode. **[anti-cheat] [vuln-research]** The exact bit meanings require the anonymous child type or disassembly.
- **`_EPROCESS::Flags3::AltSyscall`** and exported `PsRegisterAltSystemCallHandler` arrive with `PsAltSystemCallDispatch`/`PsPicoAltSystemCallDispatch`. This is an alternate syscall-dispatch capability, likely supporting specialized process environments. It is security-sensitive plumbing rather than a mitigation by itself. **[EDR] [anti-cheat] [vuln-research]**

## New security-relevant features & components (beyond mitigations)

### Hardware-backed isolation and VBS

The kernel adds a large, internally consistent IOMMU subsystem: domain create/delete/attach/detach, logical mapping, PASID, page-request queues, fault reporting, reserved regions, hypervisor-backed operations, and explicit DMA Guard policy initialization. The new DMA/HAL types and modules reinforce that this is implementation growth rather than a handful of renamed routines. **Fact:** the named routines and types are new. **Inference:** Windows 2004 is broadening device DMA isolation and its hypervisor integration. **[EDR] [anti-cheat] [vuln-research]** Confirm by diffing IOMMU policy initialization and device opt-in decisions.

Secure-pool and VSL additions (`MmAllocateSecurePoolMemory`, `PspIumAllocateSecurePool`, `VslInitializeSecurePool`, secure-page execution and secure-kernel buffer routines) indicate further VBS plumbing. These are strong hardening signals but do not prove that every path is enabled by default.

### Code integrity and signing

`ci.dll` gains `CiCheckNtHeaderForHvciCompliance`, `CiCreateHvciComplianceStatusCode`, `CiHvciLogIncompatibility`, `CipHvciPublishIncompatibleImageWNF`, CI black-box failure capture, and policy deployment routines with begin/commit/rollback semantics. **[EDR] [vuln-research]** This suggests better enforcement diagnostics plus safer policy updates. Reverse the HVCI header checks and policy transaction rollback boundaries; those are the likely bypass and parser-risk centers.

### Detection and telemetry

`EtwpTiQueryCodeIntegrityOptions`, IOMMU fault ETW events, `PopBlackBoxCodeIntegrityGuid`, CET audit loggers, and CI black-box routines expand observable failure context. **[EDR]** The data shows logging producers, but not provider access-control or event schemas; validate those before treating the signals as product-consumable telemetry.

### Cross-VM objects

`ExCrossVmEventObjectType`, `ExCrossVmMutantObjectType`, their `Exp*` lifecycle routines, extension-host guest/root paths, and cross-VM WNF delivery form a coherent component. **[vuln-research] [anti-cheat]** The object-manager access check and namespace construction in `RtlpConstructCrossVmObjectPath` are the highest-value review points.

## New attack surface (routines, callbacks, object types)

- **`PsRegisterAltSystemCallHandler`** — exported registration surface for alternate syscall dispatch. Determine which callers can register, whether registration is one-shot, and how handler pointers are protected. **[anti-cheat] [vuln-research]**
- **`MmProtectDriverSection`** — exported driver-section protection primitive. It likely supports post-load W^X or section hardening; misuse and caller authorization are worth checking. **[EDR] [anti-cheat]**
- **`NtDirectGraphicsCall` in ntdll** — a new ntdll syscall stub is visible although the kernel service is not new in the kernel diff. This is evidence of newly exposed or reorganized reachability, not proof of a new kernel handler. **[vuln-research]**
- **Win32k input and composition families** — the new service clusters substantially enlarge the GUI syscall surface. Their message capture, shared-data, handle duplication, and cross-channel visual lifetimes are natural fuzzing targets. **[vuln-research]**

## Notable structure changes

- `_FS_FILTER_PARAMETERS::AcquireForSectionSynchronization` gains a `ULONG Flags`, extending minifilter callback semantics. **[EDR] [vuln-research]** Identify the new flag values and whether old filters receive different section-acquisition behavior.
- `_EPROCESS` grows from `0x880` to `0xa40` and gains alternate-syscall, dynamic EH-continuation target tree/lock, and extensive scheduler/security state. Size alone is not a security finding; the named CET and alternate-dispatch members are.
- `_MI_HUGE_PFN` and `_MMPFN` repurpose page-state/color/channel bits for large-page metadata. Treat this as memory-manager layout change, not a mitigation claim, but update debugger and forensic parsers.

## Removed / deprecated

Win32k removes six reported services, including direct-flip pin/unpin variants, two tracked-workload calls, `NtMITSetInputSuppressionState`, and `NtUserValidateHandleSecure`. Several capabilities have obvious successors among the additions, so this looks partly like API reshaping. Do not conclude a security check vanished merely because the old handler name disappeared; trace replacement callers and implementations.

## Research leads

1. Reverse the six paired new NT services first, then inspect the two unpaired kernel entries for actual user reachability.
2. Build a win32k harness around the DXG handle/pinning, MIT message, and Moderncore process-connect clusters; preserve syscall numbers per build because of extensive renumbering.
3. Diff `PspSetupUserShadowStack`, `KeVerifyContextIpForUserCet`, and `NtContinueEx` together to map CET enforcement versus audit-only paths.
4. Trace `PsRegisterAltSystemCallHandler` registration and pointer protection, including interactions with Pico processes.
5. Reverse CI HVCI header validation and policy transaction parsing, and decode the new ETW/WNF failure records.
