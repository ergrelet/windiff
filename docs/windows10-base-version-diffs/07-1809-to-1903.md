# WinDiff analysis: Windows 10 core security binaries — 1809 → 1903 (amd64)

## Scope

- Old: Windows 10 1809 / BASE / `10.0.17763.1` · New: Windows 10 1903 / BASE / primarily `10.0.18362.1` (`ntoskrnl.exe` is `10.0.18362.30`) · Arch: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: CET/retpoline hardening, threat-intelligence telemetry, cross-VM and win32k attack surface, WDAC/CI policy, VSM, and hardware-error handling

## Executive summary

- **[EDR] [anti-cheat]** The highest-value defensive change is new Threat Intelligence coverage for driver/device-object load and unload plus queued user APC insertion. `PsNotifyWriteToExecutableMemory` appears in the same kernel, extending the theme toward executable-memory mutation visibility.
- **[all audiences]** CET state is refined from generic `CetShadowStacks` to `CetUserShadowStacks`, paired with a renamed mitigation option and user/fiber shadow-stack allocation routines. Retpoline coverage expands across kernel, HAL, boot drivers, VTL1, fixups, and image-load telemetry.
- **[EDR] [vuln-research]** `ci.dll` gains multi-policy/supplemental-policy management, policy-v6 parsing, path macros, signed policy tokens, external authorization callbacks, audit-mode state, and synthetic EA caching. This is a major WDAC architecture expansion without a new public export.
- **[vuln-research]** A new `NtCreateCrossVmEvent` native stub/export and kernel service symbols introduce cross-VM event plumbing, while win32k adds 24 and removes eight shadow services. The most sensitive GUI additions control keyboard synthesis/routing/suppression and activation-object lifecycles.
- **[vuln-research] [EDR]** WHEA adds device-driver error sources, hardware-error reporting/removal, poison clearing, SEL logging, and ETW/blackbox routing. This improves diagnostics but also creates a substantial privileged parser/callback lifecycle.
- **[vuln-research]** `cng.sys` exports four custom IEEE 802.11 SAE operations, consistent with WPA3/SAE support, and adds constant-time TLS-CBC MAC verification paths.

## New syscalls

- **`NtCreateCrossVmEvent` / `ZwCreateCrossVmEvent`** [id 160 in the `ntdll` extraction] — `ntdll` adds the syscall stub and both exports; `ntoskrnl` adds matching `NtCreateCrossVmEvent`, `ZwCreateCrossVmEvent`, and `RtlConstructCrossVmEventPath` symbols. This is strong evidence of a new native cross-VM event facility. **[vuln-research]** The kernel syscall-table extraction does not classify the service and instead reports a non-`Nt` HAL entry swap, so the exact kernel service number should be independently verified from the SSDT/disassembly before building direct-syscall tooling.
- **win32k input-control services** — `NtMITSetInputSuppressionState`, `NtMITSetKeyboardInputRoutingPolicy`, `NtMITSetKeyboardOverriderState`, and `NtMITSynthesizeKeyboardInput` add explicit routing, suppression, override, and injection operations. These are high-value anti-cheat and sandbox-boundary targets: reverse caller identity, desktop/session checks, and trusted-injector policy. **[anti-cheat] [vuln-research]**
- **win32k activation objects** — create/configure/query/destroy calls establish a new kernel object-like lifecycle. Audit reference counting, handle validation, process ownership, and teardown races. **[vuln-research]**
- **win32k pointer/visual mapping** — extended device properties, input-container IDs, pointer orientation/frame timing/proprietary IDs, visual identifiers, uniform-space mapping, and mouse-wheel routing broaden input metadata and coordinate conversion. Complex caller buffers and device lifetimes make these useful fuzzing surfaces. **[anti-cheat] [vuln-research]**
- **win32k composition/display** — shared-resource handle creation, display-manager operations, and output-duplication presentation replace some older DComposition/Dxgk calls. Shared handles and GPU queue ownership are the security-sensitive parts. **[vuln-research]**
- Same-name ID changes (303 in `ntdll`, 623 in win32k) are renumbering, not features.

## New / changed security mitigations

- **`_EPROCESS::MitigationFlags2Values::CetUserShadowStacks`** replaces `CetShadowStacks`; `_PS_MITIGATION_OPTION::PS_MITIGATION_OPTION_CET_USER_SHADOW_STACKS` similarly replaces the generic name at value `0x1f`. This is a semantic refinement, not a second new bit: 1903 makes the user-mode scope explicit. **[EDR] [anti-cheat] [vuln-research]**
- **User and fiber shadow-stack support** — kernel `PspReserveAndCommitUserShadowStack`, `PspSetupUserFiberShadowStack`, and `PspFreeUserFiberShadowStack` pair with `ntdll` exports `RtlCreateUserFiberShadowStack` and `RtlFreeUserFiberShadowStack`. This is concrete lifecycle plumbing for CET-protected fibers; actual enforcement depends on CPU/policy enablement. **[vuln-research]**
- **Retpoline completeness tracking** — `MiInitializeRetpoline`, kernel/HAL and boot-driver fixups, `MiIsImageFullyRetpolined`, `RtlIsImageFullyRetpolined`, non-retpoline image-load records, and VTL1 helpers show both enforcement machinery and visibility into incomplete coverage. **[EDR] [vuln-research]**
- **`_RTL_HP_VS_CONFIG::EnableDelayFree`** — the segment-heap variable-size allocator gains delayed-free state, plausibly increasing temporal separation between free and reuse. That security benefit is an inference; reverse allocation/free paths before treating it as a mitigation guarantee. **[vuln-research]**

## New security-relevant features & components (beyond mitigations)

- **Threat Intelligence events** — `EtwTiLogDriverObjectLoad`, `EtwTiLogDriverObjectUnLoad`, `EtwTiLogDeviceObjectLoadUnload`, and `EtwTiLogInsertQueueUserApc` directly expand the kernel TI channel. Driver/object events improve visibility into rootkit/BYOVD activity; APC insertion covers a common injection primitive. Event payloads, remote/local distinctions, provider ACLs, and suppression conditions need runtime capture. **[EDR] [anti-cheat]**
- **Executable-memory write notification** — `PsNotifyWriteToExecutableMemory` is a new process-manager symbol. Its name is directly relevant to injection/JIT monitoring, but the diff alone does not establish whether it is a public registration API, an internal dispatcher, or which writes it covers. Follow callers and any ETW/CI consumers. **[EDR] [anti-cheat] [vuln-research]**
- **WDAC multi-policy and supplemental authorization** — `SIPolicyAddPolicy`, policy lists/IDs/handles, supplemental-policy authorization, token enumeration/signature verification, policy-v6 parsing, path macros, and secure-boot checks show multiple policy artifacts being composed. `CipSiPolicyAuditModeEnabled` makes audit/enforcement state explicit; external authorization callbacks add an extensibility boundary. **[EDR] [vuln-research]**
- **CI synthetic EA cache** — `CiCreateSyntheticEaCacheContents`, image-hash-from-EA, failed signing/validation cache setters, and validation-context path/file updates indicate more verdict metadata attached to files. This can reduce repeated verification, but cache invalidation and file-identity binding deserve bypass review. **[EDR] [vuln-research]**
- **VSM/secure processes and enclaves** — `VslInitializeSecureProcess`, secure image IAT/fixups, `PsLoadVsmEnclaveData`, `MiLoadDataIntoVsmEnclave`, and `PsRequestDebugSecureProcess` expand secure-process loading and debugging control. **[EDR] [anti-cheat] [vuln-research]**
- **Device-driver WHEA sources** — exported add/remove/report APIs and `_WHEA_DEVICE_DRIVER_DESCRIPTOR` let drivers participate in hardware-error reporting; new flags route events to telemetry, internal ETW, blackbox, and SEL. This is valuable forensic coverage and new trusted-driver input surface. **[EDR] [vuln-research]**
- **802.11 SAE / TLS verification** — four `SymCrypt802_11SaeCustom*` exports add a custom SAE commit lifecycle, consistent with WPA3 authentication. `SymCryptTlsCbcHmacVerify` and `MSCryptHashDataTlsCbcHmacVerify` introduce dedicated verification paths intended to avoid padding/MAC side channels; constant-time behavior must be checked in assembly. **[vuln-research]**

## New attack surface (routines, callbacks, object types)

- **Cross-VM event creation** — namespace/path construction plus native object creation crosses a virtualization boundary. Validate path normalization, VM identity/authorization, namespace collisions, and object lifetime. **[vuln-research]**
- **Object/activation lifecycles** — the kernel separately exports `ObCreateObjectTypeEx` and `ExActivationObjectType`, while win32k adds its activation-object services. Determine which callbacks/flags the extended object-type constructor accepts, who can consume the executive type, and how the GUI activation objects validate ownership. The diff does not prove the executive and win32k objects are the same facility. **[anti-cheat] [vuln-research]**
- **Keyboard injection/routing** — the `NtMIT*` additions can alter which component receives or synthesizes input. Any weak session/window-station/trust validation could enable spoofing or cross-boundary input. **[anti-cheat] [vuln-research]**
- **WHEA driver callbacks and records** — add/remove/report/correct/ready/uninitialize operations and high-IRQL SEL handlers form a complex privileged callback surface. Audit record length/type validation and unregister concurrency. **[vuln-research]**
- **CI external authorization callbacks** — determine callback provenance, failure semantics, reentrancy, and whether an authorization provider can weaken rather than only strengthen policy. **[EDR] [vuln-research]**

## Notable structure changes

- `_EPROCESS` grows from `0x850` to `0x880`, but most emitted lines are offsets shifting together. The reliable semantic finding is the CET bit rename above; tools should not infer new process fields from the wholesale layout churn alone.
- `_KPROCESS` gains an explicit `SecureState` at the end and reorganizes group/processor scheduling arrays. This is consistent with expanded secure-process and heterogeneous scheduling work.
- `_VF_TARGET_VERIFIED_DRIVER_DATA` gains `IsBootDriver`, pairing with `VfUtilIsBootDriver` and boot-driver retpoline work. **[vuln-research]**
- `_WHEA_ERROR_SOURCE_DESCRIPTOR::Info` gains `DeviceDriverDescriptor`; `_WHEA_RECOVERY_CONTEXT::MemoryError` gains `ClearPoison`; WHEA source enums add BMC, persistent memory, and device-driver classes.
- `_MMVAD_SHORT` gains distinct private, graphics, and shared VAD flag views, a meaningful parser/reversing aid for memory-manager investigations.

## Removed / deprecated

- CET's generic `CetShadowStacks` names are removed only as they become explicitly `CetUserShadowStacks`; capability is refined, not retired.
- win32k removes older CoreMessaging and mouse-wheel synthesis calls while adding more explicit keyboard routing/synthesis and property services. This looks like protocol replacement; compare implementations before inferring a net reduction.
- `ntdll` replaces three generic WOW64 cross-process-work exports with explicit free-list/work-list variants and adds a heavy-flush request, revealing a more structured cross-process work protocol.
- The kernel syscall extractor's `xHalGetInterruptTranslator` addition and callback removal are non-`Nt` entries and should not be interpreted as user-mode native services.

## Research leads

1. Verify `NtCreateCrossVmEvent` in the 1903 SSDT and reverse path construction and VM authorization; document why kernel-table extraction misses it.
2. Capture the four new `EtwTi` event payloads and exercise driver load/unload, device-object churn, local/remote APC insertion, and blocked operations.
3. Trace `PsNotifyWriteToExecutableMemory` to registrations/consumers and determine whether it observes kernel callers, remote writes, protection changes, and JIT transitions.
4. Audit CI multi-policy precedence, supplemental authorization, policy-token signature handling, and synthetic-EA cache invalidation against rename/hardlink/reparse scenarios.
5. Fuzz activation objects and `NtMIT*` input controls across processes, desktops, sessions, and teardown races.
6. Exercise WHEA driver-source record validation and high-IRQL register/unregister races; review the SAE commit functions for invalid-point and side-channel behavior.
