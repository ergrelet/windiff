# WinDiff analysis: Windows 10 core security binaries — 1903 → 1909 (amd64)

## Scope

- Old: Windows 10 1903 / BASE / `10.0.18362.1` (`ntoskrnl.exe` is `10.0.18362.30`) · New: Windows 10 1909 / BASE / serviced `10.0.18362.x` binaries (`.295`, `.387`, or `.418`) · Arch: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: distinguish 19H2 enablement/servicing deltas from a full feature-update diff; identify any security-relevant exceptions

## Executive summary

- This is an **enablement-package/no-op-like transition**, not a conventional new-kernel jump. Every compared “1909 BASE” binary remains on the `18362` code line, at later servicing revisions, and there are **no export or syscall additions/removals in any of the seven binaries**.
- **[vuln-research]** Kernel changes are dominated by explicit `Feature_19H2_Enablement`/rollback gates and scheduler/power work: soft core parking, QoS grouping, and favored-core rotation. These are real code deltas but not new user-mode service surface.
- **[vuln-research]** `_KPRCB` exposes `VerwSelector`, and the `ntdll` type view exposes `MsrIa32TsxCtrl`; both names are consistent with CPU vulnerability-control plumbing. The diff shows storage, not when or how mitigation sequences execute.
- **[EDR] [anti-cheat]** PnP/DMA-guard servicing adds registry processing and external-DMA notification symbols, while `ci.dll` adds tenant-ID, signed-token, and secure-setting query helpers. These appear to refine existing policy paths rather than introduce new public interfaces.
- win32k and CNG changes are internal implementation/servicing churn with unchanged exports and syscall tables. This diff should not be used to claim 1909 created new GUI or crypto capabilities already present in serviced 1903.

## New syscalls

None. `ntoskrnl.exe`, `ntdll.dll`, and `win32k.sys` have identical extracted syscall sets and IDs across the compared artifacts. This is the strongest evidence that 1909's enablement did not expand the native or GUI service boundary in these binaries.

## New / changed security mitigations

- **No new named process-mitigation bit** appears in `_EPROCESS`, `_KPROCESS`, or `_PS_MITIGATION_OPTION`, and there are no resolved anonymous-member changes.
- **`_KPRCB::VerwSelector`** replaces padding at offset `0x6eaa`. The explicit `VERW` name is consistent with a selector used by CPU data-sampling mitigation sequences, but the type delta alone does not establish the instruction path or enablement condition. **[vuln-research]** Confirm in context-switch/return assembly and CPUID/microcode gating.
- **`_KPRCB::MsrIa32TsxCtrl`** replaces padding at offset `0x2d00` in the `ntdll` public type view. This directly records the IA32_TSX_CTRL MSR value; it is likely associated with TSX control for CPU security/errata handling. The field is absent from the `ntoskrnl` type delta because the reconstructed type views differ, so confirm against the 1909 kernel PDB and disassembly. **[vuln-research]**

## New security-relevant features & components (beyond mitigations)

- **19H2 staged enablement and rollback** — `Feature_19H2_Enablement*`, `Feature_19H2_Rollback*`, WIL feature-store state, and `KernelVersionBump` show capabilities being staged in the serviced 19H1 codebase and switched by feature state. This explains the small ABI delta and cautions researchers to record feature-state configuration, not only file version. **[all audiences]**
- **Scheduler/QoS/soft parking** — `_KQOS_GROUPING_SETS`, `_KNODE::SoftParkedSet`, `_PROCESSOR_POWER_STATE::SoftParked`, soft-parking ETW events, favored-core rotation, and QoS grouping code form the largest coherent feature cluster. Primarily performance/power work; security relevance is indirect through timing, processor selection, and side-channel experiment reproducibility. **[vuln-research]**
- **DMA Guard and PnP notification** — `PiDmaGuardProcessRegistry`, `PnpWinlogonExternalDmaNotification`, and related initialization symbols refine existing external-DMA policy/notification paths. This may improve device-arrival enforcement and user/session notification, but no new driver export is present. **[EDR] [anti-cheat] [vuln-research]**
- **CI tenant and secure-setting policy** — `CipGetTenantIds`, `SIPolicyLoadAuthorizationTokens`, `SiPolicyInternalQuerySecureSettingWithWildCard`, and secure-setting rollup helpers appear in `ci.dll`. They are consistent with refining multi-policy/tenant-aware WDAC support introduced in 1903. `CipInitializeSigningLevelOrder` also makes signer-level ordering explicit. **[EDR] [vuln-research]**
- **CNG servicing** — `SymCryptFatal*`, side-channel-safe table copy/rotate helpers, and SymCrypt-to-NTSTATUS mapping appear while a few integer helpers disappear. With no export delta, this is best read as a SymCrypt implementation refresh, not a new algorithm/API. **[vuln-research]**

## New attack surface (routines, callbacks, object types)

- **No new public native, GUI, CI, or CNG entry point is visible.** The remaining candidates are internal paths reachable through existing interfaces.
- **`_KALPC_RESERVE::Size`** — the kernel reserve object grows from `0x28` to `0x30` and records an explicit 64-bit size. This may harden/account for reserve-buffer bounds, but ALPC researchers should verify all producers/consumers agree on the serviced layout. **[vuln-research]**
- **Feature-state callbacks** — new WIL notification callbacks and enablement/rollback gates alter which internal code executes. They are configuration-sensitive research variables rather than user-callable attack surface by themselves.

## Notable structure changes

- `_KQOS_GROUPING_SETS` is the sole new named type in both kernel and `ntdll` datasets. `_KNODE` embeds it and adds `SoftParkedSet`; `_PROCESSOR_POWER_STATE` names the former reserved byte `SoftParked`.
- `_POWER_INFORMATION_LEVEL_INTERNAL` adds `PowerInternalSoftParkVelocityEnabled` and advances the maximum, exposing a new internal power-policy query/set class.
- `_MI_SYSTEM_PTE_STATE` adds `BreakMakePte` and shifts ultra-space mapping fields, a memory-manager implementation change worth accounting for in debugger extensions.
- win32k has no export, syscall, or type delta. `win32kbase` and `win32kfull` symbol additions/removals are balanced internal changes in DirectComposition property marshalling, input queues, surface lifetime, pen/dark-mode behavior, and related servicing.

## Removed / deprecated

- No public exports or syscalls are removed.
- Kernel `SepBuildDaclWithCriticalAces`, `SepBuildObjectSecurityDescriptor`, and `SepHasCriticalAcePresent` symbols disappear. Because they are private symbols and the build also gains substantial initialization/feature-gating code, this may be inlining/refactoring; it is not enough to claim that critical-ACE enforcement was removed.
- CNG removes three integer-size/multiply helper symbols while adding replacement/general utility functions. This looks like library refactoring.

## Research leads

1. Compare 1903 and 1909 feature-store state at runtime and exercise `Feature_19H2_Enablement` and rollback paths; treat file version plus feature state as the experimental identity.
2. Locate reads/writes of `VerwSelector` and `MsrIa32TsxCtrl` in kernel assembly to identify exact CPU-vulnerability mitigation sequences and CPUID/microcode gates.
3. Trace `PiDmaGuardProcessRegistry` and `PnpWinlogonExternalDmaNotification` through device arrival, lock-screen, and policy-change scenarios.
4. Reverse CI tenant-ID and authorization-token loading to determine policy precedence, signer ordering, and secure-setting wildcard semantics.
5. Treat win32k/CNG symbol churn as serviced implementation deltas; only elevate a finding after tying it to an existing reachable entry point and a changed validation path.
