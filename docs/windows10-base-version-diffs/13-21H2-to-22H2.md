# WinDiff analysis: Windows 10 core security surface — 21H2 → 22H2 (amd64)

## Scope

- Old: Windows 10 21H2 / BASE / `10.0.19041.1288 (WinBuild.160101.0800)`
- New: Windows 10 22H2 / BASE / `10.0.19041.2006 (WinBuild.160101.0800)`
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: redirection-trust policy, code-integrity provenance, ALPC lifetime, and GUI servicing hardening

## Executive summary

- No syscall or syscall number changes occur. Windows 10 22H2 remains on the 19041 service-table baseline; meaningful changes are policy and implementation additions.
- **[EDR] [anti-cheat] [vuln-research]** Redirection Trust is the dominant new mitigation. A policy enum, kernel policy getters/setters, token state, I/O trust computation/check exports, per-process path hashes, enforcement/audit constants, and a dedicated ETW mitigation logger all arrive together.
- **[EDR] [vuln-research]** `ci.dll` gains code-integrity origin claims, SmartLocker hashing/EA validation, signed-policy requirements, and stronger certificate revocation/timestamp helpers. This is a coherent provenance-and-policy hardening pass.
- **[vuln-research]** ALPC gains explicit canceled-queue state in `_KALPC_MESSAGE` plus new queue/port locking helpers and handle-table layout changes. This looks like cancellation/lifetime hardening and is a valuable race/UAF review target.
- **[EDR] [vuln-research]** Win32k adds unsupported-GDI telemetry and servicing gates named for a halftone out-of-bounds read, a win32k bugcheck, and matched-frame-cookie diagnostics. These names are strong patch-diff leads, not sufficient evidence of exploitability or CVE identity.

## New / changed security mitigations

- **`_PS_MITIGATION_OPTION::PS_MITIGATION_OPTION_REDIRECTION_TRUST [0x25]`** appears across kernel, ntdll, and win32k type views. The companion code is kernel-resident: `PspGetRedirectionTrustPolicy`, `PspSetRedirectionTrustPolicy`, `SeTokenGetRedirectionTrustPolicy`, `SeTokenSetRedirectionTrustPolicy`, `IoComputeRedirectionTrustLevel`, and `IoCheckRedirectionTrustLevel`. **[EDR] [anti-cheat] [vuln-research]**
- **`_EPROCESS::PathRedirectionHashes [0xa28]`** stores per-process hashes, while `MITIGATION_ENFORCE_REDIRECTION_TRUST_POLICY` and `MITIGATION_AUDIT_REDIRECTION_TRUST_POLICY` distinguish enforcement and audit paths. **Fact:** the complete policy state and helpers are present. **Inference:** Windows hashes redirected paths and evaluates their trust level against process/token policy to prevent unsafe path redirection or surface it in audit mode.
- **`EtwTimLogRedirectionTrustPolicy`** provides mitigation-specific telemetry. **[EDR] [anti-cheat]** Confirm provider identity, fields, suppression behavior, and whether audit events distinguish computed versus required trust levels.
- The new exported **`IoComputeRedirectionTrustLevel`** and **`IoCheckRedirectionTrustLevel`** make the check available to kernel components/drivers. That supports consistent enforcement, but also creates a contract whose error/default behavior must be reviewed. **[vuln-research]**

## New security-relevant features & components (beyond mitigations)

### Code-integrity provenance and policy

- `CiAddAppIdTaggingClaimsToOriginClaim`, `CiGetCodeIntegrityOriginClaimForFileObject`, `CiDeleteCodeIntegrityOriginClaim*`, and supporting `Cip*Origin*` table routines introduce explicit file-object provenance claims. Kernel `SeGetCodeIntegrityOriginClaimForFileObject`/delete helpers pair with CI. **[EDR] [anti-cheat]** This may preserve trust provenance across file handling so enforcement and telemetry can reason about origin; confirm claim lifetime across rename, section creation, and cache reuse.
- `CipSmartHashImageFile`, `CipSmartlockerGetValidEA`, `Feature_Servicing_ValidEAorHashEACheckChange`, and `SIPolicyAppIdTaggingDefaultPolicy` form a SmartLocker/AppId validation cluster. **[EDR] [vuln-research]** Review EA-versus-recomputed-hash precedence and replay/caching paths.
- `I_MinCryptIsCertificateHashRevokedV2`, `I_MinCryptIsTimestampSignerTrusted`, `MinCryptVerifySignedHash2`, and `MincryptIsTimestampBeforeRevocation` replace the older generic hash-revocation helper. **[EDR] [vuln-research]** The names imply finer certificate/timestamp semantics; test boundary times and mixed signer chains.
- `SIPolicyIsSignedPolicyRequired` and secure-setting search support indicate tighter signed-policy handling. Exact defaults are not inferable from symbol names.

### Detection and telemetry

`CiLogFileRequestedValidationEventWithProcessName` adds process identity to a CI validation event, improving attribution. `TraceLoggingWriteUnsupportedGdiUsage` is added in both win32kbase and win32kfull, with a new `CAutoGdiCallerTelemetry` type in win32k. **[EDR]** These are concrete producer additions; event provider/schema access still needs validation.

### ALPC cancellation and handle lifetime

`_KALPC_MESSAGE::u1::s1` gains the resolved one-bit `InCanceledQueue` member. `AlpcpQueryHeadCanceledQueue` and new port/view dereference and locking helpers accompany it; `_ALPC_HANDLE_TABLE` grows from `0x18` to `0x20`, moves its push lock to the front, and widens `TotalHandles` to 64 bits. **[vuln-research]** This is consistent with explicit cancellation-queue and handle-lifetime synchronization. Inspect old/new cancel, close, and rundown paths for the race being closed.

### Directory trust and containment

`LSA_FOREST_TRUST_RECORD_TYPE` gains `ForestTrustBinaryInfo [3]` and `ForestTrustScannerInfo [4]`. These are new trust-record formats/parsing cases. **[EDR] [vuln-research]** Treat them as authentication-boundary parser surface; fuzz length/type handling once their wire format is identified.

## New attack surface (routines, callbacks, object types)

- There are **no new syscalls**.
- **Two new kernel exports** implement redirection-trust calculation/checking. They are driver-facing policy surface rather than user-mode entry points. **[EDR] [anti-cheat] [vuln-research]**
- **ALPC canceled-queue paths** are internal but process attacker-controlled IPC messages. Cancellation/rundown interleavings are a high-value local-privilege-escalation research target. **[vuln-research]**
- **`_EXT_IOMMU_DEVICE_ID_FLAGS`** and a new flags member in `_EXT_IOMMU_DEVICE_ID` extend device-identity semantics. This is a small continuation of the IOMMU work introduced earlier, not evidence of a new DMA feature by itself. **[anti-cheat] [vuln-research]**

## Notable structure changes

- `_ESERVERSILO_GLOBALS` gains `ImgFileExecOptions`, suggesting per-silo image-execution-option state. **[EDR] [vuln-research]** Check whether host IFEO policy is inherited, overridden, or isolated and whether debugger/mitigation settings can leak across silo boundaries.
- `_WMI_LOGGER_CONTEXT` replaces embedded periodic-capture timer fields with a `PERIODIC_CAPTURE_STATE_CONTEXT*` and is reorganized. This is telemetry infrastructure/lifetime change, not proof of a new event source.
- `_IO_COMPLETION_CONTEXT` gains a 64-bit `UsageCount` in recovered kernel/ntdll type views, continuing explicit lifetime accounting also seen in win32k one release earlier.
- `_FADT` gains `hypervisor_vendor_identity`, and HAL enlightenment callbacks add reference-time restore state. These are virtualization-awareness changes, not standalone mitigations.

## Removed / deprecated

No syscalls or exports are removed. In CI, `I_MinCryptIsHashRevoked` is replaced by certificate-specific V2 and timestamp-aware helpers, and `SIPolicyFilePathRulesPresent` disappears while origin/AppId tagging and signed-policy helpers expand. This suggests policy refactoring, not evidence that path rules ceased to exist.

## Research leads

1. Map the Redirection Trust policy API end to end: process policy input, token state, path hashing, trust computation, audit event, and enforcement failure.
2. Test path canonicalization, reparse points, mount points, case/Unicode normalization, and time-of-check/time-of-use behavior around `PathRedirectionHashes`.
3. Trace CI origin claims across file-object duplication, rename, image-section creation, and cache replay; test EA/hash disagreement.
4. Patch-diff ALPC cancellation, close-message, and handle-table teardown to reconstruct the fixed race and build concurrency tests.
5. Reverse the named win32k halftone OOB-read servicing gate and matched-frame-cookie telemetry without assuming a specific vulnerability identity.
6. Recover and fuzz the new forest-trust binary/scanner record parsers.
