# WinDiff analysis: Windows 10 core security surface — 20H2 → 21H1 (amd64)

## Scope

- Old: Windows 10 20H2 / BASE / `10.0.19041.508 (WinBuild.160101.0800)`
- New: Windows 10 21H1 / BASE / `10.0.19041.928 (WinBuild.160101.0800)`
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: CET enforcement/auditing, process hardening, and win32k lifetime changes

## Executive summary

- No syscall or syscall number changes occur in any compared binary. This is another enablement-package-scale transition with internal hardening rather than new service-table reachability.
- **[all]** 21H1 makes the strongest CET advance since 2004: `_EPROCESS` gains strict-mode, non-CET blocking, audit, dynamic-API, and relaxed IP-validation bits, backed by explicit enforcement and ETW mitigation loggers.
- **[EDR] [anti-cheat]** `_EPROCESS::DisallowUserTerminate` adds named per-process termination-control state. It is potentially useful for protected service/self-defense scenarios, although the raw diff does not identify which process API or policy sets it.
- **[vuln-research] [anti-cheat]** Win32k input-lock exports are replaced with forms carrying reference/unreference context, while touch-frame cleanup is added. This is consistent with tighter pointer-message lifetime management and is a strong race/UAF patch-diff lead, not proof of a specific fixed vulnerability.
- **[anti-cheat] [vuln-research]** EH-continuation guard tables spread across kernel, ntdll, both win32k implementation binaries, CI, and CNG, indicating broad build-level control-flow hardening.

## New / changed security mitigations

- **`_EPROCESS::MitigationFlags2Values`** gains one-bit fields `CetUserShadowStacksStrictMode`, `BlockNonCetBinaries`, `BlockNonCetBinariesNonEhcont`, `AuditBlockNonCetBinaries`, `AuditBlockNonCetBinariesLogged`, `CetDynamicApisOutOfProcOnly`, and `UserCetSetContextIpValidationRelaxedMode`, plus five reserved bits. This is direct policy-state evidence, not anonymous-type churn. **[all]**
- **Enforcement and audit pairing** — `PsBlockNonCetBinaries`, `KeIsCetCapable`, `KeIsKernelCetEnabled`, `KeSetUserCetAppcompatOptions`, `KiCheckUserAddressCetCompat`, and `RtlGuardCheckExceptionHandler` appear beside `MITIGATION_ENFORCE_*`/`MITIGATION_AUDIT_*` constants and `EtwTimLogBlockNonCetBinaries`, `EtwTimLogControlProtectionUserModeReturnMismatch`, and `EtwTimLogUserCetSetContextIpValidationFailure`. **Fact:** enforcement and logging routines are present. **Inference:** 21H1 can enforce or audit CET compatibility at image load, context changes, and exception continuation depending on process policy. **[EDR] [anti-cheat] [vuln-research]**
- **`_MI_EXTRA_IMAGE_INFORMATION` CET flags** — the structure grows to `0x10` and records image shadow-stack readiness, strict mode, relaxed IP validation, and in-process dynamic-API allowance. This ties process policy to per-image compatibility state. **[vuln-research]** Probe downgrade rules for images without EH continuation metadata.
- **`_PS_DYNAMIC_ENFORCED_ADDRESS_RANGES` in `_EPROCESS` [0xa10]** — new per-process storage for dynamically permitted CET-compatible regions, paired with ntdll min/max dynamic callback-table trees. **[vuln-research] [anti-cheat]** Dynamic exceptions to control-flow policy are prime bypass-review targets.
- **Broad `/guard:ehcont` evidence** — `__guard_eh_cont_table`/`count` appear across six of seven binaries. Validate each image's load configuration before asserting runtime enforcement. **[anti-cheat] [vuln-research]**

## New security-relevant features & components (beyond mitigations)

### Detection and telemetry

The three new `EtwTimLog*` routines provide mitigation-specific logging for blocked non-CET images, control-protection return mismatches, and set-context IP validation failures. **[EDR] [anti-cheat]** Their names indicate kernel ETW emission, but not that they belong to the public Threat Intelligence provider; map provider GUIDs and event descriptors before integrating them.

### Process and anti-tamper state

`_EPROCESS::Flags3` gains `DisallowUserTerminate` at bit 27. **Fact:** named state exists. **Inference:** it likely prevents some user-mode termination path and could support protected workloads or servicing. **[EDR] [anti-cheat]** Confirm setters, access checks, and whether kernel termination remains possible.

### Loader/runtime read-only data

Ntdll adds `LdrProtectMrdataHeap`, `RtlpProtectReadOnlyHeap`, and `RtlpProtectInvertedFunctionTable`. This suggests more loader/runtime metadata is transitioned to read-only protection, reducing writable control data. **[EDR] [anti-cheat] [vuln-research]** Reverse write windows and failure fallbacks.

## New attack surface (routines, callbacks, object types)

There are no new syscalls. The notable internal surface is policy and lifetime machinery:

- **`PsBlockNonCetBinaries` and CET appcompat shims** decide when non-CET targets remain loadable. **[vuln-research]** Review relaxed/basic modes and the targeted hook-driver shim for downgrade opportunities.
- **Win32k `CInpLockGuard` reference-aware APIs** replace lock methods that used a generic lock-entry stack. New `CRefUnRefPointerMsgId` plumbing and `CleanupInputDestHwndRefsForDesktopThreadExit` suggest explicit message-object lifetime tracking. **[vuln-research]** Diff callers for missing reference transfers on error paths.
- **`NotifyProtocolViolationHelper` in CoreMessaging** indicates a new explicit malformed-protocol path. **[vuln-research]** Determine whether untrusted clients can drive it and how messages are captured.

## Notable structure changes

- `_DYNAMIC_FUNCTION_TABLE` grows from `0x70` to `0x88`, replacing one tree node with `TreeNodeMin` and `TreeNodeMax`. This supports range-oriented dynamic function table indexing and should be considered when studying CET dynamic-code exceptions.
- `_PS_ATTRIBUTE_NUM::PsAttributeMitigationAuditOptions [0x1b]` formalizes mitigation audit policy at process creation.
- `_KUSER_SHARED_DATA::UserCetAvailableEnvironments` becomes reserved in this build's recovered type view. Because the CET implementation simultaneously expands elsewhere, this is best treated as a layout/API exposure change, not CET removal.

## Removed / deprecated

No syscalls or exports are removed from the kernel, ntdll, win32k syscall layer, CI, or CNG. Removed CET audit routine names (`KiLogControlProtectionUserModeAudit`, `KiProcessControlProtectionUserModeAudit`, and related) are replaced by more specific failure loggers; this looks like refinement, not telemetry loss.

## Research leads

1. Trace each new `_EPROCESS` CET bit from process creation and `NtSetInformationProcess` through image mapping and exception dispatch.
2. Compare audit-only and enforcing ETW event paths, including provider GUID, access control, and event suppression/logged bits.
3. Fuzz dynamic enforced address ranges and callback-table updates under concurrent image unload.
4. Patch-diff old/new win32k input-lock callers for reference-counting changes that reveal fixed UAF/race conditions.
5. Find all setters/readers of `DisallowUserTerminate` and test its behavior across ordinary, protected, and job-contained processes.
