# WinDiff analysis: Windows 10 core security surface — 2004 → 20H2 (amd64)

## Scope

- Old: Windows 10 2004 / BASE / `10.0.19041.264 (WinBuild.160101.0800)`
- New: Windows 10 20H2 / BASE / `10.0.19041.508 (WinBuild.160101.0800)`
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: security-relevant changes in an enablement-package-scale delta

## Executive summary

- No NT or win32k syscall is added, removed, or renumbered. The 20H2 BASE image therefore preserves the externally visible service tables in these seven binaries.
- **[EDR]** `win32kbase.sys` exports `EtwTraceUiAuditReadClipboard`, a narrowly named clipboard-read audit producer and the clearest new defensive visibility in this transition.
- **[EDR] [vuln-research]** `ci.dll` adds dynamic-catalog management, certificate publisher-name extraction, and custom-signing-policy trust update logic. These extend CI policy plumbing without changing the syscall boundary.
- **[vuln-research] [anti-cheat]** Kernel symbols show continued CFG/retpoline-aware driver-image finalization, while win32k gains EH-continuation guard tables. These are build-hardening signals; the raw diff does not establish their default enforcement state.
- Most remaining type churn is physical-memory/DMA bookkeeping. It matters to symbol consumers and crash analysis but should not be promoted into a security feature claim.

## New / changed security mitigations

- **CET policy enum visibility in `win32k.sys`** — `_PS_MITIGATION_OPTION` gains `PS_MITIGATION_OPTION_BLOCK_NON_CET_BINARIES [0x21]` and `PS_MITIGATION_OPTION_CET_DYNAMIC_APIS_OUT_OF_PROC_ONLY [0x24]`; `_PS_ATTRIBUTE_NUM` gains `PsAttributeMitigationAuditOptions [0x1b]`. **Fact:** these shared type definitions become visible in this binary's PDB. **Inference:** this is preparatory or shared-header exposure, because the kernel diff has no matching resolved `_EPROCESS` bits or enforcement routines in this transition. Do not date full enforcement from these types alone. **[all]**
- **EH-continuation metadata in win32k** — `__guard_eh_cont_table` and `__guard_eh_cont_count` appear in `win32k.sys`. This is consistent with `/guard:ehcont` metadata and hardens permitted exception-continuation targets when honored by the platform. **[anti-cheat] [vuln-research]** Confirm PE load-config flags and table entries.
- **Driver image hardening helpers** — `MiInitializeKernelCfg`, `MiFinalizeDriverImage`, and `MiFinalizeImageRetpolineState` appear in the kernel. They indicate CFG/retpoline-aware image finalization, but names alone do not prove a newly enabled global policy. **[EDR] [anti-cheat]**

## New security-relevant features & components (beyond mitigations)

### Detection and telemetry

- **`EtwTraceUiAuditReadClipboard`** is both a new `win32kbase.sys` export and a debug symbol; `win32kfull.sys` imports it. That cross-binary pairing shows the full GUI implementation emitting through a base-layer ETW audit helper. **[EDR] [anti-cheat]** It likely closes a clipboard-read visibility gap, useful for detecting credential/data theft or automation, but the event schema and provider permissions must be checked before operational use.
- `EtwTraceGdiCreateHandle` and `EtwTraceAcquiredSharedUserCrit` add narrower GUI diagnostics. These appear more diagnostic than threat-intelligence-specific; do not equate them with `EtwTi`.

### Code integrity and signing

- **`CiGetCertPublisherName`** becomes a new CI export, paired with `MincryptParseRDNComponents`/`CipBuildNameFromRdnValues`. This makes publisher identity a first-class result in CI evaluation or logging. **[EDR] [vuln-research]** Audit malformed RDN handling and confirm whether the value feeds policy, telemetry, or both.
- **`CiAddDynamicCatalog`, `CiRemoveDynamicCatalogs`, `CiDeinitializeCatalogs`** add runtime catalog lifecycle paths. **[EDR] [vuln-research]** Dynamic trust stores introduce concurrency, lifetime, and policy-transition questions even if callers are privileged.
- **`CipUpdateOemTestCertTrustFromCustomSigningPolicy`** and `SeCodeIntegritySetInformation`/`SepGetSystemSigningLevel` show coordinated custom-signing and signing-level work across CI and the kernel. **[EDR] [anti-cheat]** Reverse the privilege gate (`CiIsPermissionsElevatedOrSystem` and imported `SeSinglePrivilegeCheck`) and update ordering.

## New attack surface (routines, callbacks, object types)

- There are **no new syscalls**. New surface is kernel-internal or driver-facing.
- **`MmGetCacheAttributeEx`** is the sole new kernel export. It extends cache-attribute querying; security relevance is mainly to DMA/device and driver correctness. **[vuln-research]** Compare accepted address/range forms with the non-Ex variant.
- Win32k input-lock helpers and GDI handle accounting change (`HmgIncProcessHandleCountEx`, `EnterSharedCritAvoidingDitHitTestHazard`). These look like lifetime/concurrency maintenance rather than new reachability. **[vuln-research]** They are useful patch-diff anchors for race fixes.

## Notable structure changes

- `_ADAPTER_OBJECT` gains an expiration lock and state (`ExpiredLock`, `ExpiredFlag`) and grows from `0x278` to `0x280`. This is consistent with safer DMA adapter allocation lifetime management. **[vuln-research]** Verify all teardown paths acquire the new lock.
- `_EXT_IOMMU_DEVICE_ID_PCI` changes a five-bit field from `DevicePathLength` to reserved and adds a full `USHORT DevicePathLength`. That widens representable path length and changes parser layout; update forensic/debugger decoders.
- `_MMPFN::u4` adds `ResidentPage` and repurposes prior large-page bits, while several `_MI_*` structures expand large/huge-page state. These are real memory-manager changes, not direct evidence of a mitigation.

## Removed / deprecated

No exports, syscalls, or types are removed from the kernel, ntdll, win32k, CI, or CNG in a way that indicates retired security functionality. Removed debug symbols are mostly replaced helpers or feature-state churn.

## Research leads

1. Decode and exercise the clipboard audit event; determine whether protected/AppContainer/UIAccess cases are covered.
2. Reverse CI dynamic-catalog locking and teardown, then fuzz certificate RDN parsing through signed catalog inputs.
3. Check PE load-config metadata for EH-continuation guard activation in win32k and compare enforcement with the CET work in later releases.
4. Audit `_ADAPTER_OBJECT` expiration transitions for double-use or stale DMA mappings.
