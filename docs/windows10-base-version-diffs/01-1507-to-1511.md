# WinDiff analysis: Windows 10 1507 → 1511 core security surface (amd64)

## Scope

- Old: Windows 10 1507 / BASE / `10.0.10240.16384 (th1.150709-1700)`
- New: Windows 10 1511 / BASE / `10.0.10586.0 (th2_release.151029-1700)`
- Architecture: amd64
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: new kernel and GUI syscalls, process mitigations, isolation, defensive callbacks, code integrity, and cryptographic assurance

## Executive summary

- **[vuln-research][EDR] Enclaves become a first-class native service.** `NtCreateEnclave`, `NtInitializeEnclave`, and `NtLoadEnclaveData` appear in the kernel syscall table and as `Nt*`/`Zw*` exports in `ntdll`. Memory-manager state (`_MMVAD_FLAGS::Enclave`, enclave page lists, and `LoaderEnclaveMemory`) and new trustlet types show that this is a coherent protected-execution subsystem rather than name-only churn.
- **[EDR][anti-cheat] Process creation observation gains an extended registration API.** The kernel exports `PsSetCreateProcessNotifyRoutineEx2`. Its name and pairing with existing process callbacks establish a new callback contract; the precise notification classes and caller restrictions require prototype/disassembly review.
- **[anti-cheat][vuln-research] Image-loading and child-process policy are tightened.** `_EPROCESS::Flags3` gains `ProhibitRemoteImageMap`, `ProhibitLowILImageMap`, and `SignatureMitigationOptIn`; `_PS_ATTRIBUTE_NUM` adds `PsAttributeChildProcessPolicy`. These are direct process-hardening state additions, although the raw diff does not establish their default policy or enforcement path.
- **[EDR][vuln-research] Server-silo isolation matures.** New `PsGet*ServerSilo` APIs, silo-aware I/O/object state, and a private object namespace in `_OBP_SILODRIVERSTATE` expand the kernel boundary used by containers. This reduces accidental cross-container sharing but also creates new namespace and lifetime logic worth auditing.
- **[vuln-research] win32k changes are smaller but still user-reachable.** Nine GUI/GDI services are added, including input-device teardown, protected-output/certificate queries, and DirectComposition operations; four older composition/display services disappear.

## New syscalls

### NT kernel

- **`NtCreateEnclave`** [157] — creates the kernel object/address-space state for an enclave. Paired `ntdll` exports: yes (`NtCreateEnclave`, `ZwCreateEnclave`). The associated `KeCreateEnclave`, `MiAllocateEnclaveVad`, and `_MMVAD_FLAGS::Enclave` additions make this a confirmed new memory-manager path. Impact: a new privileged parser/state machine is reachable from user mode. **[vuln-research]** Confirm by reversing `NtCreateEnclave` and its `Mi*` allocation/validation callees.
- **`NtInitializeEnclave`** [240] — initializes the previously created protected region. Paired `ntdll` exports: yes. Impact: caller-supplied initialization metadata crosses the syscall boundary and should be fuzzed separately from creation. **[vuln-research]**
- **`NtLoadEnclaveData`** [248] — loads pages into an enclave. Paired `ntdll` exports: yes. The new enclave page lists, enclave VAD bit, and `LoaderEnclaveMemory` value corroborate a dedicated loading path. Impact: page provenance, permissions, signing, rollback, and partial-failure cleanup become new audit targets. **[vuln-research][EDR]**

The 275 NT syscall renumberings follow insertion of these services and are not feature additions. They matter to direct-syscall tooling, which must use the build-specific table.

### win32k

The shadow table adds nine services and removes four. The higher-signal additions are:

- **`NtUserRemoveInjectionDevice`** [5143] — extends synthetic-input device lifecycle management. The name alone indicates teardown, not a new injection authorization bypass, but ownership and handle validation deserve review. **[anti-cheat][vuln-research]**
- **`NtGdiGetCertificateByHandle`** [4778] and **`NtGdiGetCertificateSizeByHandle`** [4780] — expose certificate material associated with a graphics/protected-output handle. These likely support protected media/output negotiation; malformed handle and size paths are the primary research angle. **[vuln-research]**
- **`NtGdiDdDDISetHwProtectionTeardownRecovery`** [4635] — manages recovery during hardware-protection teardown. This adds state transitions around protected graphics sessions. **[anti-cheat][vuln-research]**
- `NtCompositionSetDropTarget`, `NtDCompositionAttachMouseWheelToHwnd`, `NtGdiDdDDIFlushHeapTransitions`, `NtSetCompositionSurfaceBufferCompositionModeAndOrientation`, and `NtUserUpdateWindowTrackingInfo` round out the new surface. These are mostly composition/input functionality, but remain kernel GUI entry points.

Removed services are `NtDCompositionSignalGpuFence`, `NtGdiDdDDINetDispStartMiracastDisplayDeviceEx`, `NtSetCompositionSurfaceBufferCompositionMode`, and `NtUserSetImmersiveBackgroundWindow`. The orientation-aware replacement for the composition-mode API suggests interface evolution; it is not evidence that the underlying behavior vanished.

## New / changed security mitigations

- **`_EPROCESS::Flags3::ProhibitRemoteImageMap`** (bit 11), **`ProhibitLowILImageMap`** (bit 12), and **`SignatureMitigationOptIn`** (bit 13) — the data directly shows three new per-process state bits. They are consistent with blocking remote-origin images, blocking low-integrity image mappings, and opting into stronger signature policy. The diff does not show their policy setters, audit mode, or defaults. **[EDR][anti-cheat][vuln-research]** Confirm by tracing writes to `Flags3` from process creation and `NtSetInformationProcess` paths.
- **`_PS_ATTRIBUTE_NUM::PsAttributeChildProcessPolicy`** [0x14] — exposes child-process policy during process creation. This is consistent with a parent constraining descendant creation, a useful containment and anti-spawn primitive. **[EDR][anti-cheat]** Confirm by following the attribute in `PspCreateUserProcess` and checking whether it maps to enforcement, inheritance, or both.
- **`_MMVAD_FLAGS::Enclave`** (bit 18) — marks a VAD as enclave-backed. This is functional state for the new enclave implementation rather than a standalone exploit mitigation, but it changes VAD invariants and page-fault behavior. **[vuln-research]**

No resolved anonymous-member change was emitted for this transition. The named `_EPROCESS` and `_MMVAD_FLAGS` deltas above are therefore the strongest type evidence; no hidden anonymous mitigation bit is being inferred.

## New security-relevant features & components (beyond mitigations)

### Extended process notification

`PsSetCreateProcessNotifyRoutineEx2` is a new exported callback-registration API. It likely adds selectable notification semantics or a versioned payload beyond `Ex`, but that is an inference from the suffix; the raw diff does not supply a prototype. For EDR and kernel anti-cheat, this may expose additional process classes or richer creation context. **[EDR][anti-cheat]** Confirm by recovering the signature from public symbols and comparing validation/dispatch with `PsSetCreateProcessNotifyRoutineEx`.

### Server silos and namespaces

New exports include `PsGetCurrentServerSilo`, `PsGetProcessServerSilo`, `PsGetJobServerSilo`, `PsGetSiloIdentifier`, and related queries. `_EJOB` changes its container representation, `_IO_DRIVER_CREATE_CONTEXT` gains silo context, `_ETW_SILODRIVERSTATE` grows substantially, and `_OBP_SILODRIVERSTATE` gains `PrivateNamespaceLookupTable`. Together these facts show wider subsystem participation in server-silo isolation. **[EDR][anti-cheat][vuln-research]** Security products must interpret process identity and telemetry in the correct silo; researchers should test namespace lookup, teardown, and cross-silo handle lifetime.

### Cryptographic self-test auditing

The kernel newly exports `SeAuditFipsCryptoSelftests`; `cng.sys` imports it and adds `SymCryptAesSelftest`, while `ci.dll` adds `SymCryptSha384Append` and a second certificate-policy verifier. This is consistent with better assurance and auditability of cryptographic initialization, not a new algorithm exposed to callers. **[EDR][vuln-research]** Confirm event provider/fields and failure behavior, especially whether self-test failure is fail-closed.

## New attack surface (routines, callbacks, object types)

- **Enclave memory-management cluster** — `KeAddEnclavePage`, `KeCreateEnclave`, `KeInitializeEnclave`, `MiAddPagesToEnclave`, `MiAllocateEnclaveVad`, and debug read/write helpers form a new stateful subsystem. Bugs in range validation, page ownership, or debug authorization could cross isolation boundaries. **[vuln-research]**
- **`ObOpenObjectByNameEx`** — an extended object-manager lookup export. Its security relevance depends on the new parameters; object namespace and access-check handling should be compared with the base routine. **[anti-cheat][vuln-research]**
- **win32k protected-output and input paths** — the certificate, hardware-protection recovery, and injection-device APIs combine handles, variable-sized buffers, and mutable session state, all common kernel GUI bug patterns. **[anti-cheat][vuln-research]**

## Notable structure changes

- `_KUSER_SHARED_DATA` gains `EnclaveFeatureMask[4]`, providing an explicit user-visible capability bitmap.
- `_MI_USER_VA_INFO` gains `NumberOfDebugEnclaves`, while `_MI_PARTITION_PAGE_LISTS` gains `EnclavePageListHead`; these corroborate dedicated enclave accounting.
- `_TOKEN` grows an `IndexEntry` pointer. The name suggests indexed token lookup/accounting, but no security behavior should be assigned without tracing consumers.

## Removed / deprecated

The removal of several older silo-object exports (`PsGetSiloObject`, `PsInsertSiloObject`, and peers) alongside the new server-silo API family looks like interface replacement rather than abandonment of isolation. The four removed win32k services similarly coincide with replacement composition/display paths. Researchers maintaining private-symbol tooling should account for both transitions.

## Extraction caveats

`ntdll.dll` reports 443 added syscalls because its old syscall count is zero and its new count is 443. That is an extraction-coverage discontinuity, not 443 newly introduced services. Only the three enclave services are corroborated by `ntoskrnl.exe` and new `ntdll` exports. The large win32k renumbering set is also table regeneration, not 835 new capabilities.

## Research leads

1. Recover prototypes and fuzz the three enclave syscalls as a stateful sequence, including rollback and concurrent teardown.
2. Reverse `PsSetCreateProcessNotifyRoutineEx2` to identify new notification classes, integrity requirements, and callback payload lifetime.
3. Trace setters and enforcement sites for the three new `_EPROCESS::Flags3` bits and `PsAttributeChildProcessPolicy`.
4. Audit silo-private object namespace creation and teardown for stale handles or cross-silo name resolution.
5. Compare protected-output certificate and hardware-teardown handlers in win32k with their user-mode thunk validation.
