# WinDiff analysis: Windows 10 core security binaries — 1803 → 1809 (amd64)

## Scope

- Old: Windows 10 1803 / BASE / `10.0.17134.1` · New: Windows 10 1809 / BASE / `10.0.17763.1` · Arch: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: speculative-execution/CET mitigation state, hotpatching, Threat Intelligence ETW, code integrity, TLS, and win32k attack surface

## Executive summary

- **[all audiences]** 1809 turns the 1803 speculative-isolation foundation into explicit per-process policy: `_EPROCESS` gains named bits for indirect-branch restriction, security-domain isolation, page-combine disablement, speculative-store-bypass disablement, and CET shadow stacks. Retpoline and control-protection routines appear alongside them.
- **[EDR] [anti-cheat]** The Threat Intelligence channel gains `EtwTiLogSuspendResumeProcess` and `EtwTiLogSuspendResumeThread`, plus asynchronous VAD-query event writers. This closes visibility gaps around process/thread suspension and suspicious memory layouts.
- **[vuln-research]** `NtManageHotPatch` replaces `NtLoadHotPatch`, paired across kernel and `ntdll`, while a broad memory-manager/VSL hotpatch implementation appears. This is a privileged, stateful patch lifecycle and a strong reversing target.
- **[EDR] [vuln-research]** `ci.dll` adds HVCI relocation-table handling, supplemental-policy paths, developer dynamic signers, policy-v5 parsing, and explicit enforcement/audit outcomes. The theme is richer WDAC policy and observability rather than a new CI export.
- **[vuln-research]** win32k adds 27 shadow services (11 removed), including tracked GPU workloads, input-space/cursor routing, safer HWND-call variants, and DPI/foreground controls.
- **[vuln-research]** `cng.sys` exposes `SslExportKeyingMaterial` and adds TLS 1.3 encrypt/decrypt and label-expansion symbols, a clear protocol-capability expansion.

## New syscalls

- **`NtCreateSectionEx`** [id 185] — added in the kernel and mirrored by `NtCreateSectionEx`/`ZwCreateSectionEx` exports in `ntdll`. It extends section creation, so object attributes, extended parameters, image/data-section distinctions, and privilege checks are the likely validation boundary. **[vuln-research]**
- **`NtManageHotPatch`** [id 266] — added in both kernel and `ntdll`, replacing `NtLoadHotPatch`/`ZwLoadHotPatch`. The name and supporting routines show a move from a one-way load operation to a management interface that can apply, enumerate, and revert process, driver, and secure-image patches. **[EDR] [vuln-research]** Confirm accepted operation codes, signer/privilege gates, and rollback ownership by reversing the dispatcher.
- **win32k tracked-workload services** — eight `NtDxgk*TrackedWorkload*` calls plus hardware-queue presentation add a GPU workload accounting/control protocol. Attack surface centers on indexes, statistics buffers, lifetime, and device-context ownership. **[anti-cheat] [vuln-research]**
- **win32k input-space and safe HWND calls** — `NtConfigureInputSpace`, cursor/pointer input-space setters, three `NtUserCallHwnd*Safe` variants, shell cursor state, and application foreground control alter input/window authorization paths. “Safe” is an implementation claim worth testing against stale/reused handles and cross-desktop callers. **[anti-cheat] [vuln-research]**
- **win32k DPI services** — defer/restore DPI changes and query current DPI/cursor sizes expand per-window transition state. Lower security priority, but asynchronous window destruction and cross-process HWND use remain useful race targets. **[vuln-research]**
- The 259/267 kernel/native and 925 win32k same-name renumberings are table rebuild noise unless a tool hardcodes service numbers.

## New / changed security mitigations

- **`_EPROCESS::MitigationFlagsValues::RestrictIndirectBranchPrediction`** and **`IsolateSecurityDomain`** — named process bits replace one reserved bit. They directly represent the branch-prediction and security-domain mechanisms whose infrastructure appeared in 1803. **[all audiences]**
- **`_EPROCESS::MitigationFlags2Values::SpeculativeStoreBypassDisable`** — direct process state for SSBD. Enforcement and hardware support should be confirmed through `KiSetHardwareSpeculationControlFeatures` and `KiUpdateSpeculationControl`. **[vuln-research]**
- **`_EPROCESS::MitigationFlags2Values::DisablePageCombine`** — prevents page combining for opted-in processes, plausibly reducing cross-process content deduplication side channels. The security rationale is an inference from the name; reverse the mitigation setter and memory-manager check. **[anti-cheat] [vuln-research]**
- **`_EPROCESS::MitigationFlags2Values::CetShadowStacks`** — first explicit CET shadow-stack process bit in this sequence. New `KiControlProtectionFault`, `KeVerifyContextXStateCetU`, software shadow-stack PTE checks, and user-shadow-stack cleanup show implementation plumbing, but this diff alone does not prove broad hardware enforcement on shipping CPUs. **[EDR] [anti-cheat] [vuln-research]**
- **Retpoline infrastructure** — exported `KeReenterRetpolinedCode`, `VslInitializeRetpoline`, `MiApplyRetpolineFixups`, and guarded retpoline thunks show kernel/VTL support for indirect-branch hardening. This is implementation hardening rather than a user-selectable policy bit. **[vuln-research]**

## New security-relevant features & components (beyond mitigations)

- **Threat Intelligence telemetry** — `EtwTiLogSuspendResumeProcess` and `EtwTiLogSuspendResumeThread` are direct additions. `EtwpTiVadQueryEventWrite`, its asynchronous work-item form, and thread-identity/VAD fillers indicate richer memory-region context. EDR and anti-cheat products gain visibility into suspension-based tampering and memory inspection/evasion workflows, subject to provider access controls and actual event enablement. **[EDR] [anti-cheat]**
- **Managed hotpatch lifecycle** — the kernel adds apply/unapply, per-process and per-SID contexts, undo pages/tables, boot-driver patching, logging, and secure/VSL revert support. Hotpatching reduces reboot exposure for fixes but also creates a high-privilege image-mutation mechanism. **[EDR] [vuln-research]**
- **Code integrity / WDAC** — `CipHvciFindDynamicRelocationTable`, `CipRegisterDeveloperDynamicSigners`, `CipGetSupplementalPolicyPath`, `SIPolicyParseV5Data`, and `SIPolicyQueryWindowsLockdownMode` form a coherent policy expansion. Named `SiPolicy*Failure` and `*Audit` symbols show separate enforcement and audit outcomes for Windows, ATP, SKU, and driver revocation policy. **[EDR] [vuln-research]**
- **VSM enclave telemetry** — `ntdll` gains loader telemetry for VSM enclave create/delete/initialize/module-load operations. This is user-mode loader instrumentation, not proof that unprivileged consumers can subscribe to all resulting events. **[EDR] [vuln-research]**
- **TLS 1.3 / exporter support** — `cng.sys` adds `Tls13EncryptPacket`, `Tls13DecryptPacket`, `TlsExpandLabel`, `TlsExportKeyingMaterial`, and the new `SslExportKeyingMaterial` export. This adds protocol and key-derivation code paths; malformed record lengths, exporter label/context handling, and downgrade transitions are the main audit targets. **[vuln-research]**

## New attack surface (routines, callbacks, object types)

- **Hotpatch management** — complex apply/revert operations span process images, drivers, boot patches, VSL, mapped pages, and undo state. Validate authorization, image identity, race handling, and rollback after partial failure. **[vuln-research]**
- **`NtCreateSectionEx`** — expanded section-construction inputs may reach image parsing and memory-manager paths not selected by the legacy service. **[vuln-research]**
- **win32k input/GPU state machines** — tracked-workload indexes, material properties, input-space regions, foreground changes, and “safe” HWND dispatch are new user-to-kernel paths with cross-object invariants. **[anti-cheat] [vuln-research]**
- **`KeSetSystemServiceCallback` / system-service trace callback state** — new callback registration and tables can support tracing, but any reachable registration or callback-target validation weakness would be sensitive. Determine caller restrictions and `KeIsValidTraceCallbackTarget` coverage. **[EDR] [anti-cheat] [vuln-research]**

## Notable structure changes

- `_EPROCESS` acquires five named mitigation bits across its two mitigation words; these are the most meaningful type deltas.
- `_CONTROL_AREA` gains `AweSection` and `ImageBaseOkToReuse`, consistent with finer section-type/reuse state around the new section/hotpatch work.
- `_IO_STACK_LOCATION` read and write arms gain `Flags`. This is driver-facing ABI state and should be checked for consumers that assume the older union shape.
- `_HEAP_SEG_CONTEXT::Flags` gains a three-bit `LargePagePolicy`, revealing explicit segment-heap large-page selection rather than a security mitigation by itself.

## Removed / deprecated

- `NtLoadHotPatch` and `ZwLoadHotPatch` are removed as `NtManageHotPatch` arrives. This is a replacement/generalization, not a retirement of hotpatch capability.
- win32k removes older DWM input-output configuration and monitor-brightness services while adding input-space and shell-cursor abstractions. Verify whether functionality moved to Dxgk/user-mode brokers before concluding the surface shrank.
- Several reserved `FsRtl*` context exports disappear from `ntoskrnl`; no direct user-mode attack-surface reduction follows from that export change.

## Research leads

1. Recover the `NtManageHotPatch` operation schema and privilege/signature checks; exercise interrupted apply/revert and cross-process/SID cases.
2. Trace the five new `_EPROCESS` bits from process mitigation setters into context-switch and memory-manager enforcement.
3. Capture and decode the new `EtwTi` suspend/resume and VAD-query events, including provider ACLs and conditions that suppress events.
4. Audit CI supplemental-policy and developer-signer authorization, especially audit-versus-enforce transitions and dynamic relocation parsing under HVCI.
5. Fuzz TLS 1.3 record and exporter inputs through the existing CNG/Schannel dispatch that reaches the new `cng.sys` routines.
