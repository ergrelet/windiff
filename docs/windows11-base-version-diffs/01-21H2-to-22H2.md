# WinDiff analysis: Windows 11 core security surface — 21H2 → 22H2 (amd64)

## Scope

- Old: Windows 11 21H2 / BASE / kernel and win32k `10.0.22000.194 (WinBuild.160101.0800)`
- New: Windows 11 22H2 / BASE / kernel and win32k `10.0.22621.382 (WinBuild.160101.0800)`
- Component builds differ slightly: old `cng.sys` is `22000.1`, `ci.dll` is `22000.100`, and `ntdll.dll` is `22000.120`; their new builds are `22621.4`, `22621.317`, and `22621.317`, respectively.
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: new system-call surface, process/core isolation, alternate syscall providers, memory-safety instrumentation, code integrity, GUI/GPU attack surface, and DMA isolation

## Executive summary

- **[vuln-research]** Five native services are genuinely new and paired with ntdll stubs: `NtCopyFileChunk` plus create/open/query/set operations for CPU-partition objects. The kernel raw diff reports five additional non-`Nt*` entries, but companion-table checks show those are extraction artifacts rather than user-mode system calls.
- **[anti-cheat] [vuln-research]** The release adds `PS_MITIGATION_OPTION_RESTRICT_CORE_SHARING`, an `_EPROCESS::MitigationFlags3Values::RestrictCoreSharing` bit, per-process CPU-partition linkage, thread core-isolation reasons, and a full CPU-partition API. Together these show a coherent scheduler isolation feature intended to keep an opted-in process from sharing physical-core resources.
- **[EDR] [anti-cheat] [vuln-research]** A new syscall-provider subsystem adds three kernel exports, per-process provider state, VSL publication hooks, and generic dispatch paths. The names show configurable per-process system-service routing; its precise trust boundary and intended client require reversing before treating it as either a defensive primitive or an interception surface.
- **[vuln-research]** The kernel gains exported KASAN/ASAN shadow-memory and load/store instrumentation helpers, plus driver image load/unload tracking. This materially improves Microsoft's ability to detect memory corruption in instrumented kernels or drivers, but does not by itself protect uninstrumented production code.
- **[EDR] [vuln-research]** `ci.dll` gains a large Smart App Control/Night's Watch policy cluster: Defender signals, enforcement-mode transitions, verified-and-reputable decisions, dynamic-code trust logging, policy refresh, and richer CI telemetry. This is the strongest defensive-control change in the comparison.
- **[vuln-research]** Win32k adds eleven services: seven GPU scheduling/synchronization calls and four GDI/User calls for text readiness, clipboard metadata, docking targets, and tooltip dismissal. These are real shadow-table additions with matching stubs or implementations, and they substantially outweigh the fifteen retired legacy/telemetry calls as patch-diff targets.

## New syscalls

### Native NT services

- **`NtCopyFileChunk` [id 165]** — a new I/O-manager service with a matching `NtCopyFileChunk`/`ZwCopyFileChunk` ntdll pair. Kernel helpers `IoCheckFileObjectOpenedAsCopySource`, `IoCheckFileObjectOpenedAsCopyDestination`, `_COPY_INFORMATION`, and several `IopFreeCopyObjects*` paths show that it copies ranges between file objects rather than merely wrapping a user-mode read/write loop. The new validation, offset, completion, cancellation, and lifetime paths are fresh filesystem attack surface. **[vuln-research]** Confirm by tracing both file-object access checks and fuzzing overlapping ranges, sparse/compressed files, cancellation, and cross-volume/provider behavior.
- **`NtCreateCpuPartition` [id 166]**, **`NtOpenCpuPartition` [id 292]**, **`NtQueryInformationCpuPartition` [id 338]**, and **`NtSetInformationCpuPartition` [id 418]** — four new process/scheduler services, each paired with `Nt*` and `Zw*` exports in ntdll. Kernel symbols create a `PsCpuPartitionType`, CPU-partition directory/name state, a default security descriptor, process assignment lists, and move/delete/query machinery. They expose a new securable scheduling object, so object ACLs, ownership, cross-job access, CPU-set validation, and concurrent CPU movement deserve review. **[anti-cheat] [vuln-research]** Confirm by recovering the information-class structures and access masks from the handlers.

The raw `ntoskrnl.exe` extractor also labels `LpcReplyWaitReplyPort`, `IopPnPAddDevice`, `xHalIommuFinalizeDeviceReset`, `xHalAllocateMessageTarget`, and `NtSetLowWaitHighEventPair` as additions, with five corresponding removals. These do **not** represent five more user-mode services: four are not `Nt*` entry points, and the event-pair routines are both present and merely renumbered in ntdll. Only the five additions above are confirmed by the independently extracted ntdll table. The 316 ntdll renumberings and 300 kernel renumberings are service-table rebuild noise, relevant only to software that hard-codes service numbers.

### Win32k shadow services

- **`NtDxgkConnectDoorbell` [4426]**, **`NtDxgkCreateDoorbell` [4427]**, and **`NtDxgkDestroyDoorbell` [4430]** — a new GPU doorbell lifecycle. Doorbells typically connect user-mode queue submission to a device-visible notification mechanism; mapping, ownership, stale-handle, and teardown races are the key security questions. Matching win32k stubs are present. **[anti-cheat] [vuln-research]**
- **`NtDxgkCreateNativeFence` [4428]** and **`NtDxgkOpenNativeFenceFromNtHandle` [4442]** — new native GPU synchronization-object creation/import paths. Cross-process handle import and fence lifetime introduce object-validation and synchronization attack surface. **[anti-cheat] [vuln-research]**
- **`NtDxgkEnumProcesses` [4436]** and **`NtDxgkNotifyWorkSubmission` [4441]** — new graphics-process enumeration and work-submission notification services. Their names imply new GPU scheduling/telemetry coordination; authorization and information-disclosure behavior should be tested from AppContainer and low-integrity callers. **[EDR] [anti-cheat] [vuln-research]**
- **`NtGdiWaitForTextReady` [4900]** — a matching `win32kfull.sys` implementation adds a wait boundary around GDI text/font readiness. Its likely security value is indirect: asynchronous font/render state is historically rich in lifetime bugs, so cancellation and object teardown are worthwhile patch-diff targets. **[vuln-research]**
- **`NtUserGetClipboardMetadata` [5143]** — paired with `InternalGetClipboardMetadata` in win32kfull. Clipboard data crosses process, desktop, session, and integrity boundaries; validate metadata length, ownership checks, and whether protected formats leak information without data access. **[EDR] [vuln-research]**
- **`NtUserRegisterForCustomDockTargets` [5349]** and **`NtUserRegisterForTooltipDismissNotification` [5350]** — new window-registration services backed by dock-target and tooltip-registration helpers. These extend HWND/callback-style state and should be tested for cross-process window spoofing, stale registrations, and destruction races. **[vuln-research]**

## New / changed security mitigations

- **`_PS_MITIGATION_OPTION::PS_MITIGATION_OPTION_RESTRICT_CORE_SHARING [0x26]`** appears in the kernel, ntdll, and win32k type views. In the new kernel database, the newly added `_EPROCESS::MitigationFlags3` word at offset `0xb70` resolves to **`RestrictCoreSharing : 1` at bit 0**. `PspApplyCoreIsolationPolicy`, `KeIsCoreIsolationMitigationPolicyEnforceable`, and `_KTHREAD_CORE_ISOLATION_REASON::KThreadCoreIsolationReasonMitigationPolicy` are direct companion changes. **Fact:** this release adds a named process mitigation and runtime state. **Inference:** it prevents affected processes from co-scheduling on sibling logical processors, reducing SMT side-channel exposure and hostile same-core observation. **[EDR] [anti-cheat] [vuln-research]** Confirm enforcement and inheritance by reversing `PspApplyCoreIsolationPolicy` and observing sibling-thread placement under load.
- **`_KTHREAD::SecureThread` [bit 8 at offset `0x74`]** and **`_KTHREAD::CoreIsolationReasons` [offset `0x461`]** replace spare storage, while `_KPROCESS` gains `CpuPartitionList`. These are implementation state for secure-thread and core-partition scheduling, not separate user-selectable mitigations. **[anti-cheat] [vuln-research]**
- **`_KPRCB::BpbKCet` [bit 3 at offset `0xf9`]** appears in the shared win32k type view, while kernel symbols add boot kernel shadow-stack initialization and `KiUserCetPl3SspCanonicalizeUpperMask`. This is consistent with continued kernel/user CET plumbing, but the diff does not prove that a previously disabled CET policy became enabled by default. **[EDR] [anti-cheat] [vuln-research]**
- **`_KUSER_SHARED_DATA::UserPointerAuthMask` [offset `0x730`]** and new system information classes for pointer authentication and secure-kernel debugging reserve architecture/security capability reporting. On `amd64`, these declarations are forward-compatible surface rather than evidence that pointer authentication is active. **[vuln-research]**

## New security-relevant features & components (beyond mitigations)

### Alternate syscall providers and VBS integration

`PsRegisterSyscallProvider`, `PsUnregisterSyscallProvider`, and `PsQuerySyscallProviderInformation` become kernel exports. Internal `PspAttachProcessToSyscallProvider`, inheritance, opt-in, provider lookup, service-table metadata, and generic dispatch routines arrive with `_EPROCESS::SyscallProvider`, process links, and dispatch context. `VslPublishSyscallProviderServiceTables` and `VslRegisterSyscallProviderServiceTableMetadata` connect the mechanism to the virtualization/security layer.

**Fact:** the kernel can now associate a process with a registered provider and dispatch provider-owned service-table slots. **Inference:** this likely supports an isolated or specialized execution environment rather than arbitrary user-mode syscall hooks; registration is kernel-facing, and the diff does not reveal caller policy. A compromised signed driver might nevertheless target this control plane, while defenders and anti-cheat authors need to understand whether provider dispatch changes syscall-observation assumptions. **[EDR] [anti-cheat] [vuln-research]** Confirm by reversing registration authorization, provider lifetime/rundown, process inheritance, and VSL publication.

### Kernel Address Sanitizer plumbing

The kernel exports `KasanMarkAddressInvalid`, `KasanMarkAddressRedZone`, `KasanMarkAddressValid`, `KasanTrackAddress`, `KasanValidateAddress`, the `__asan_load*`/`__asan_store*` families, report routines, poisoned-stack helpers, and instrumented memory-operation wrappers. `KasanInitSystem`, `KasanDriverLoadImage`, and `KasanDriverUnloadImage` complete a coherent shadow-memory instrumentation subsystem.

This is security testing infrastructure: instrumented kernel and driver builds can detect out-of-bounds and use-after-free accesses nearer to the fault. It is highly valuable for driver fuzzing and root-cause analysis, but no claim of transparent production protection follows from symbol presence alone. **[vuln-research]** Confirm enablement requirements and shadow layout through `KasanInitSystem` and `KasaniShadow`.

### Smart App Control, dynamic-code trust, and CI telemetry

- `CiHandleDefenderSignals`, `CiSetNightsWatchPolicyStateRegKeys`, `CiCatDbSendSmartAppControlBlockToast`, `CiCatDbSendSmartAppControlSwitchEnforceToast`, and state globals for switching Night's Watch to enforcement mode form an explicit Defender-driven policy-transition path. The same diff adds `SIPolicyVerifiedAndReputableAllowAntiMalware`, `...AllowUnknown`, and `...UI`. **Inference:** Night's Watch is the internal policy path underlying the release's Smart App Control/reputation enforcement. **[EDR] [anti-cheat]** Reverse signal authentication and state persistence; a spoofed downgrade or stale boot-state transition would be security-sensitive.
- `CiQueryDynamicCodeTrustClaim`, `CiLogQueryDynamicCodeTrust`, `CiDynamicCodeTrustFailed`, and a servicing gate named `WldpQueryDynamicCodeTrustLog` expand visibility around dynamic-code trust decisions. The older `CiValidateDynamicCodePages`/`CiHvciValidateDynamicCodePages` symbols disappear, so this looks like a refactor toward claim/query-based enforcement rather than evidence that HVCI validation was removed. **[EDR] [vuln-research]**
- Four newly visible Microsoft-Windows-Security-CodeIntegrity provider annotations, `CiAuditDriverLoad`, `CiLogFileRequestedValidationEventWithProcessName`, origin-claim instrumentation, and missing-catalog telemetry improve attribution around image/driver decisions. **[EDR]** Validate provider GUIDs, schemas, and consumer permissions before relying on the events.
- `CiAsyncPolicyRefreshRoutine`, `CipDeleteOldPolicies`, wildcard/additional-condition matching, conditional policy IDs, and resource-loading policy expand WDAC/SI policy lifecycle and rule evaluation. These are defensive gains and also parser/state-machine review targets. **[EDR] [vuln-research]**

### DMA/IOMMU and secure-device state

`VslGetSecurePciDeviceBootConfiguration` becomes a kernel export; new ATS/SVM routines configure device address translation and validate page-request GPAs; and `_IOMMU_DMA_DEVICE::Native` gains `SourceId`, `AtsReferenceCount`, `InvalidationQueueDepth`, and `DeviceActive` rundown state. `SystemIommuStateInformation` and hybrid-passthrough reserved-region types expose more platform state.

This is consistent with deeper DMA remapping and VBS-aware device isolation, including explicit lifetime accounting for address-translation services. It can reduce DMA attacks, but ATS/SVM invalidation, device reset, power transition, and rundown are complex privileged state machines worth auditing. **[anti-cheat] [vuln-research]** Confirm ordering guarantees in `IvtConfigureAts`, `IvtDrainSvmPageRequests`, and device deletion/reset paths.

### Cryptographic assurance

`cng.sys` adds DSA sign/verify and self-test routines, RSA/ECDH/ECDSA self-tests, PKCS#7 padding helpers, and a newer SymCrypt implementation cluster without changing its exports. `ci.dll` and the kernel also gain certificate-specific revocation and signed-hash helpers such as `I_MinCryptIsCertificateHashRevokedV2` and `MinCryptVerifySignedHash2`. **Fact:** cryptographic validation and self-test internals expanded. **Inference:** this is an assurance/implementation refresh, not evidence of a new externally callable algorithm. **[EDR] [vuln-research]** Test failure handling and boundary inputs rather than treating symbol churn as a new protocol.

## New attack surface and notable structure changes

- **ALPC cancellation and handle lifetime:** `_KALPC_MESSAGE::u1::s1` gains `ViewAttributeDeleteOnRelease` and `InCanceledQueue`; `_ALPC_HANDLE_TABLE` grows from `0x18` to `0x20`, moves its push lock, and widens `TotalHandles` to 64 bits. `AlpcpQueryHeadCanceledQueue` and explicit port/queue lock helpers accompany the layout changes. This is consistent with cancellation, view cleanup, and rundown hardening around attacker-controlled IPC. **[vuln-research]** Patch-diff cancel/close races and malformed view-attribute handling.
- **Job resource controls:** `_EJOB` gains effective and requested I/O/page priority limits, and `_JOBOBJECTINFOCLASS` adds `JobObjectIoPriorityLimit [0x30]` and `JobObjectPagePriorityLimit [0x31]`. These are new containment/QoS controls exposed through an existing job syscall, not new services. **[EDR] [anti-cheat] [vuln-research]** Check nested-job inheritance and integer/range validation.
- **Forest-trust parsing:** `LSA_FOREST_TRUST_RECORD_TYPE` gains `ForestTrustBinaryInfo [3]` and `ForestTrustScannerInfo [4]`. These are new authentication-boundary record formats and therefore parser/fuzzing targets once their serialized forms are recovered. **[EDR] [vuln-research]**
- **Per-silo policy:** `_ESERVERSILO_GLOBALS` gains `ImgFileExecOptions`, suggesting silo-specific image-execution-option state. Determine whether debugger and mitigation settings inherit, override, or leak across the container boundary. **[EDR] [vuln-research]**
- **Bad-handle diagnostics:** `_ETHREAD` consumes a spare bit for `GenerateDumpOnBadHandleAccess`. This is diagnostic hardening/telemetry rather than access-control enforcement, but it may improve triage of handle misuse. **[EDR] [vuln-research]**
- **Additional user/runtime surface:** ntdll adds `RtlCallEnclave`, heap custom-memory callbacks, and work-on-behalf ticket helpers without corresponding new syscalls. These are supporting runtime contracts; enclave transition and custom allocator callback validation are the most security-relevant review targets. **[vuln-research]**

## Removed / deprecated

- Win32k removes six `NtDCompositionTelemetry*` animation/touch-interaction calls and nine older User services: `NtUserAllowForegroundActivation`, `NtUserDirectedYield`, `NtUserInitTask`, `NtUserRegisterUserHungAppHandlers`, `NtUserSetCursorContents`, `NtUserWOWCleanup`, `NtUserWOWModuleUnload`, `NtUserWaitForMsgAndEvent`, and `NtUserYieldTask`. This shrinks those direct shadow-table entry points, although implementation relocation or consolidation must be ruled out before claiming the underlying behavior vanished. **[vuln-research]**
- Kernel export `KeSetTracepoint` is removed while new dynamic-tracing suspend/resume/hibernate routines and per-processor tracepoint-log state appear. That suggests tracing infrastructure refactoring, not removal of kernel tracing.
- CI's generic `I_MinCryptIsHashRevoked` is replaced by certificate-specific V2 and timestamp-aware helpers. The change indicates finer revocation semantics; it does not mean hash revocation stopped.

## Research leads

1. Reverse all four CPU-partition handlers, recover object access masks and information classes, then test privilege checks, namespace ACLs, partition deletion, concurrent CPU moves, and job/process inheritance.
2. Trace `PS_MITIGATION_OPTION_RESTRICT_CORE_SHARING` from the process policy setter through `PspApplyCoreIsolationPolicy` to scheduler placement; measure whether SMT siblings are idled or reserved and how failures are reported.
3. Map syscall-provider registration, VSL publication, per-process inheritance, and teardown. Determine the intended provider, required caller trust, and how EDR/anti-cheat syscall telemetry sees provider-dispatched calls.
4. Build or obtain a KASAN-enabled driver/kernel environment and fuzz driver IOCTL paths; verify red-zone coverage, quarantine behavior, unload cleanup, and report quality.
5. Fuzz `NtCopyFileChunk` across filesystem types with cancellation, overlapping ranges, sparse/compressed/encrypted files, oplocks, and filter drivers.
6. Audit GPU doorbell/native-fence object ownership, shared mappings, handle import, reset, and process teardown; separately test `NtDxgkEnumProcesses` for low-privilege disclosure.
7. Reverse Night's Watch/Smart App Control mode transitions, Defender signal handling, dynamic-code trust claims, and policy refresh persistence. Validate that audit/enforce downgrades cannot be spoofed or raced.
8. Patch-diff ALPC canceled-queue/view cleanup and ATS/SVM device rundown for the synchronization bugs their new explicit state may have closed.
