# WinDiff analysis: Windows 11 core security surface — 22H2 → 23H2 (amd64)

## Scope

- Old: Windows 11 22H2 / BASE / `10.0.22621.382 (WinBuild.160101.0800)` (`ntoskrnl.exe`)
- New: Windows 11 23H2 / BASE / `10.0.22621.2428 (WinBuild.160101.0800)` (`ntoskrnl.exe`)
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`, `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: process mitigations, GUI syscall surface, DMA isolation, speculative-execution hardening, code integrity, and servicing fixes

This comparison needs an attribution caveat. Both labels resolve to binaries on the
`22621` servicing line: the kernel moves from revision 382 to 2428 rather than to a
distinct 22631 binary baseline. Individual files also have their own revisions
(`ci.dll` is 22621.317 → 22621.2361 and `cng.sys` is 22621.4 → 22621.1992).
The report therefore describes what is present in the two WinDiff BASE snapshots;
it does **not** prove that every delta was introduced by the 23H2 enablement package
itself. Numerous `Feature_*` and `Feature_Servicing_*` symbols strongly indicate a
mixture of dormant-feature enablement and cumulative servicing work.

## Executive summary

- **[EDR] [anti-cheat] [vuln-research]** A new FSCTL process mitigation is the clearest policy addition. `_PS_MITIGATION_OPTION` gains `PS_MITIGATION_OPTION_FSCTL_SYSTEM_CALL_DISABLE`, `_EPROCESS` gains enforcing and auditing state bits, and kernel code gains an FSCTL classifier and a feature gate.
- **[vuln-research]** Win32k exposes four confirmed GUI services: three for shell handwriting-input delegation and one for shell hot-key registration. Matching `win32k.sys` stubs and `win32kfull.sys` implementations make these genuine additions; their authorization and message-lifetime rules are the main review targets.
- **[EDR] [anti-cheat] [vuln-research]** The IOMMU stack receives a substantial PASID/SVM and secure-ATS expansion, including a V3 interface, new domain/device state, Hyper-V plumbing, and a new secure-kernel service. This is a meaningful DMA-isolation capability change as well as complex privileged attack surface.
- **[all]** New per-processor RSB-flush, kernel-CET, branch-confusion, and SRSO state/routines show a speculative-execution hardening pass. Because this is a serviced 22621 comparison, the data supports presence in the later payload, not exclusive attribution to 23H2.
- **[EDR] [vuln-research]** `ci.dll` adds a coherent Smart App Control, SmartScreen-claim, Defender-instrumentation, UMCI-revalidation, AppId-tagging, and signature-expiry cluster, plus two Code Integrity network-activity ETW providers.
- **[vuln-research]** Named win32k and filesystem servicing gates point to concurrency, object-lifetime, leak, and validation fixes. They are excellent patch-diff leads, but their names alone do not establish exploitability or a CVE mapping.

## New syscalls

### Confirmed win32k services

- **`NtUserShellHandwritingDelegateInput`** [5492], **`NtUserShellHandwritingHandleDelegatedInput`** [5493], and **`NtUserShellHandwritingUndelegateInput`** [5494] add a shell-specific input-delegation lifecycle. `win32k.sys` contains matching syscall stubs and `win32kfull.sys` contains the implementations, supported by message lookup/reassignment, delegate-thread cleanup, pointer-message locking, and dedicated `InputTraceLogging` events. **Fact:** the callable surface and companion implementation are new. **Inference:** it lets a trusted shell path transfer handwriting/input-message handling between threads or consumers. Impact: delegated messages, thread teardown, and object ownership introduce local attack surface around stale queue entries, cross-thread trust, and use-after-free conditions. **[vuln-research] [anti-cheat]** Confirm by reversing the access checks, caller-mode probing, queue ownership changes, and cleanup paths.
- **`NtUserShellRegisterHotKey`** [5496] adds a shell-specific hot-key registration path. It is paired across the win32k stub and implementation layers with new child-hot-key and shell-reporting helpers. The `Shell` qualifier suggests restricted shell semantics, but the diff does not reveal who is authorized. Impact: registration collisions, window/queue ownership, desktop/session isolation, and input injection boundaries deserve review. **[vuln-research] [anti-cheat]**

The four insertions shift 56 later win32k service numbers. That renumbering is table
layout churn, not 56 additional features, but direct-syscall tooling must update its
service-number map.

### ntoskrnl extraction artifact

The raw kernel diff reports five additions and five removals, but it does **not**
support five new NT services. Four alleged additions are non-`Nt` routines
(`xHalQueryBusSlots`, `xHalTimerQueryCycleCounter`, `BvgaSetVirtualFrameBuffer`,
and `xHalConfigureLastBranchRecord`), while four removals are likewise internal
HAL/I/O/LPC names. The remaining apparent substitution is
`NtSetHighWaitLowEventPair` for `NtSetLowWaitHighEventPair`, yet `ntdll.dll` has
no syscall or corresponding stub change. This is inconsistent with the NT service
table contract and is treated as extraction/alignment noise. No new kernel `Nt*`
syscall is confirmed by this comparison.

## New / changed security mitigations

### FSCTL system-call disable policy

- **`_PS_MITIGATION_OPTION::PS_MITIGATION_OPTION_FSCTL_SYSTEM_CALL_DISABLE [0x27]`** appears in the recovered kernel, ntdll, and win32k type views. **[EDR] [anti-cheat] [vuln-research]**
- **`_EPROCESS::MitigationFlags3Values`** gains the one-bit fields `DisallowFsctlSystemCalls` and `AuditDisallowFsctlSystemCalls`; the spare field contracts from 31 to 29 bits. Kernel symbols add `MITIGATION_ENFORCE_PROHIBIT_FSCTL_SYSTEM_CALLS`, `MITIGATION_AUDIT_PROHIBIT_FSCTL_SYSTEM_CALLS`, `Feature_FsctlProcessMitigation`, `IoFsctlProcessMitigationEnabled`, and `IopIsStandardFsctlIoControlCode`. **Fact:** enforcement and audit state, a feature gate, and a control-code classifier exist. **Inference:** the process policy can reject or audit selected filesystem-control requests issued through existing I/O syscalls, reducing exposure to risky FSCTL handlers without adding a new syscall. The diff does not identify the allowed/blocked code set or an ETW consumer. Confirm by reversing the classifier and the `NtFsControlFile`/I/O dispatch path, then testing enforcing versus audit-only behavior across local, network, and filter-backed filesystems.

### Speculative-execution state

- **`_KPRCB`** gains `BpbFlushRsbOnReturn`, `BpbFlushRsbOnRetpolineExit`, their trapped-state counterparts, and `BpbKCet`. New routines include `KiIsBranchConfusionPresent`, `KiIsBranchConfusionMitigationDesired`, `KiIsKvaShadowNeededForBranchConfusion`, `KxReenterRetpolinedCode`, and `KiIsSrsoMitigationDesired/Enabled/Supported`. **[all]** This is direct evidence of new per-CPU control state and selection logic for return-stack-buffer flushing, kernel CET interaction, branch-confusion handling, and SRSO mitigation. It does not show which processors enable each path by default. Confirm with a disassembly diff of mitigation selection during processor initialization and context transitions, correlated with CPUID/microcode conditions.

## New security-relevant features & components (beyond mitigations)

### IOMMU, PASID, and secure ATS

The kernel adds `_DMA_IOMMU_INTERFACE_V3`, PASID-specific device-creation types,
`_IOMMU_BUS_INTERFACE`, device information/state types, and a
`DomainTypeTranslateS1` domain. `_IOMMU_DMA_DEVICE` expands from `0x108` to
`0x1a0` with PASID-tagged-DMA, default-PASID, SVM capability, creation-state, and
device-list fields. `_IOMMU_DMA_DOMAIN` expands from `0x40` to `0x70` with a
wider ASID, attached-device tracking, Hyper-V references, and a push lock;
`_IOMMU_TRACKED_DEVICE` expands from `0x70` to `0x1070` and gains 512 group-fault
references.

The structural work pairs with `IommuPasidDeviceCreate/Delete`, PASID domain
attach/detach, enable/disable/flush helpers, Hyper-V PASID calls, and feature gates
named `IommuApiPasid`, `Kernel_DMA_Compliance`, and `SecureDevAts`. The secure
boundary also gains `VslConfigureSecureAtsDevice`,
`ExAtsSvmSecureDevicePowerCallback`, and
`_SKSERVICE::SECURESERVICE_CONFIGURE_SECURE_ATS_DEVICE [0x10e]`.

**Fact:** the later payload has a broader PASID-aware IOMMU state machine and a
new secure-kernel configuration operation. **Inference:** this supports finer
device address-space isolation/shared virtual memory while bringing ATS enablement
under a secure policy boundary. **[EDR] [anti-cheat]** Better DMA isolation raises
the bar for malicious or compromised devices. **[vuln-research]** Device attach,
power transition, fault suppression, group-fault bookkeeping, and partial-create
rollback paths are high-value lifetime and bounds targets. Confirm on PASID-capable
hardware and under Hyper-V with DMA-verifier instrumentation.

### Code Integrity and Smart App Control

- `CiCheckSmartScreenClaim`, `CiCatDbMpSmartLockerEnable`, `SSCatDBMpSmartLockerEnable`, `CiHandleFlagsFromDefender`, and `CiInstrumentSmartAppControlDecision*` form a SmartScreen/Smart App Control/Defender decision cluster. Gates named `SAC_Validly_Signed`, `SACIgnoreAutoOptOut`, `SAC_DefenderDisabledOnUpgrade`, and `RevalidateNoUMCI` show that signing validity, upgrade state, Defender state, and UMCI revalidation are explicit policy concerns. **[EDR] [vuln-research]** These names support the policy relationship; they do not reveal precedence or default enablement. Test OOBE/upgrade transitions, Defender-disabled states, and cached reputation/signing claims.
- `SIPolicyAppIdTaggingEnforceDLL` and the `WdacAppidTaggingPerfImprovements` gate extend AppId-tagging enforcement/performance, while `SIPolicyIsSidKnownAdmin` adds an administrator-identity check in CI policy code. **[EDR] [anti-cheat] [vuln-research]** Reverse policy-cache lifetime and DLL-versus-image handling, especially across token changes and file replacement.
- `CiLogSignatureExpiryEvent` and two named `MicrosoftWindowsSecurityCodeIntegrityNWActivity` TraceLogging providers add signature-expiry and network-activity instrumentation. **[EDR]** The producer names indicate new observability, but provider schema, enablement, and consumer availability require runtime ETW capture before treating them as dependable telemetry.

No new `EtwTi*` Threat Intelligence producer appears in the seven-binary delta;
the CI providers above are distinct Code Integrity instrumentation and should not
be described as EtwTi coverage without runtime provider/schema confirmation.

### Filesystem/filter synchronization and diagnostics

The kernel exports `ExAcquireFastResourceWithFlags`,
`ExInitializeFastResourceAcquired`, and `ExMoveFastResourceOwnershipWithFlags`,
while a much larger internal `FastResource2` implementation appears. It also
exports `FsRtlCheckOplockForFsFilterCallback`,
`FsRtlDisallowLegacyFilterOnDevice`, and
`FsRtlOpenFileSystemRegistryKeyFromFsGuid`. Servicing gates name
`OplockCancelTracing`, `OplocksWritableMappedSectionsFix`, and
`CopyEABufferHandling`.

**Inference:** this is a synchronization/ownership and filter-coordination pass,
with explicit attention to oplock cancellation, mapped sections, and EA-buffer
handling. **[EDR]** Minifilter authors should check compatibility with the new
oplock callback and legacy-filter exclusion behavior. **[vuln-research]** Oplock
cancellation, ownership transfer, and malformed EA buffers are concrete race and
memory-safety patch-diff leads. None of these exports is a new user-mode entry
point.

### Live-dump protection and process filtering

`Feature_LivedumpProcessFiltering` accompanies
`IopLiveDumpAddProcessFilter`, `IopLiveDumpLookupProcessFilter`,
`IopLiveDumpExcludeProtectedProcesses`, and
`IopLiveDumpValidateProtectedProcessExclusions`. **Fact:** the later kernel can
filter process content and names protected-process exclusion explicitly.
**Inference:** live-dump collection can avoid disclosing protected-process pages
or restrict capture scope. This matters to EDR dump acquisition and PPL/anti-cheat
self-protection, while exclusion logic is also a potential forensic blind spot.
**[EDR] [anti-cheat] [vuln-research]** Confirm which protection levels are
excluded and whether kernel aliases, shared pages, or race-time process changes can
bypass the filter.

### Win32k servicing hardening and input telemetry

- Feature gates named `CFONTPrintLeak`, `HMAllocPreventOrphanObjects`, `DWMResourceTypeFix`, `GdiUmpdDisableLock`, and `GdiResetRecursiveBatch` identify work around font/printing lifetime, handle-manager orphan prevention, DirectComposition/DWM resource typing, user-mode display-driver locking, and recursive GDI batch state. **[vuln-research]** These are strong locations for old/new control-flow comparison, but a gate name is not proof of a security vulnerability.
- `CInpLockGuard` drops a broad guard/waiter API and gains simpler shared/exclusive lock guards plus explicit pointer-message reference/unreference helpers. Paired handwriting cleanup and pointer-message coalescing additions make input-message lifetime the likely concern. **[vuln-research] [anti-cheat]** Stress termination, WER/DWM transitions, delegation cancellation, and concurrent pointer-frame coalescing.
- Background raw-mouse throttling adds timer/threshold helpers and events for throttle and flush behavior. **[anti-cheat] [EDR]** This changes input timing and provides diagnostics, but is not itself evidence of an anti-cheat control. Establish whether injected and physical input traverse identical accounting paths.

## New attack surface (routines, callbacks, object types)

- The four confirmed `NtUser*` services are the principal new user-to-kernel surface. The handwriting trio carries messages and thread/queue ownership; the shell hot-key path manages global-ish input registration. Both require authorization and teardown review. **[vuln-research]**
- PASID/IOMMU configuration is primarily privileged driver, hypervisor, and secure-kernel surface, not a new ordinary-user syscall. Its large new state machine nevertheless creates attack surface for a compromised driver/device and for malformed fault or power-transition sequences. **[anti-cheat] [vuln-research]**
- `FileStatBasicInformation`, four extended directory-information classes, and `FileFsGuidInformation` are added to the recovered file-information enums. They expand operations reachable through existing file-information syscalls rather than adding service-table entries. **[vuln-research]** Check buffer sizing, filesystem-specific implementations, and mixed 64/128-bit file-ID handling.
- `_IO_STACK_LOCATION::Parameters::MountVolume` gains `OutputBufferLength` across recovered type views, pairing with new mount/filesystem information work. Drivers compiled against or interpreting this union should be checked for version-safe length validation. **[EDR] [vuln-research]**

## Notable structure changes

- **`_W32PROCESS::bGDILimitReachedAtLeastOnce`** records whether a process has hit its GDI limit. It likely supports one-shot diagnostics or policy decisions; the field alone does not show enforcement behavior.
- **`_EXT_IOMMU_S1_X64_DOMAIN_SETTINGS::Flags`** gains `Blocked` and `EnableDefaultPasid`; `_HAL_HV_DMA_DOMAIN_CONFIG_X64` gains `Blocked`. These provide explicit default-deny/block state within the new DMA-domain machinery. **[anti-cheat] [vuln-research]**
- **`_IOMMU_SVM_CAPABILITIES::CapReg`** gains `PriPrgResponsePasidRequired`, indicating that page-request responses may need an associated PASID on some hardware. Incorrect capability negotiation is a concrete interoperability and isolation test case.
- **`_INTERRUPT_REMAPPING_INFO::u::Msi::MessageData`** widens from 16 to 32 bits. That is a real ABI/layout change in interrupt-remapping state; audit producers/consumers for truncation assumptions.
- **`_CM_KCB_LAYER_INFO`** gains `DiscardedUpperLayerListHead`, and `_CM_UOW_SET_SD_DATA` gains a hive pointer. These suggest registry layered-state cleanup and security-descriptor transaction context. Their security impact is uncertain; hive unload/rollback concurrency is the best confirmation target.
- ReFS compression controls change from a single synchronous-compress flag to start, stop, and garbage-collection operations. This broadens stateful filesystem-control behavior through existing interfaces and merits malformed-transition testing, but is not evidence of a new mitigation.

## Removed / deprecated

- No export is removed from ntoskrnl, ntdll, win32k, win32kfull, CI, or CNG. `win32kbase.sys` removes 18 exports while adding 16, principally replacing the older `CInpLockGuard`/pointer-message contract with the new locking API; this is interface refactoring rather than removal of GUI syscalls.
- `_HAL_HV_SVM_SYSTEM_CAPABILITIES` is removed as the HAL/Hyper-V interface shifts from `Svm*`-named operations to broader PASID terminology and adds `_HAL_HV_SYSTEM_PASID_CAPABILITIES`. The paired additions show evolution, not retirement of SVM functionality.
- CI removes `CiInstrumentOriginClaim` while adding Smart App Control/Defender decision instrumentation and network-activity providers. The data supports telemetry refactoring, not loss of origin/reputation checking.
- CNG changes a SymCrypt build/self-test string, adds checked-integer helpers, and replaces one WPP trace GUID. With no export, syscall, or type change, this is insufficient evidence of a new cryptographic primitive or externally visible crypto interface.

## Research leads

1. Reverse the FSCTL mitigation from process-policy parsing through `IopIsStandardFsctlIoControlCode`; enumerate affected controls and compare enforcement, audit, and feature-disabled behavior.
2. Fuzz all four new win32k services across malformed handles/messages, cross-desktop and cross-session callers, delegate-thread exit, repeated delegate/undelegate operations, and hot-key collision teardown.
3. Patch-diff the 22621.382 and 22621.2428 branch-confusion/SRSO paths and build a CPU/microcode matrix for RSB flush and `BpbKCet` activation.
4. Exercise PASID device creation through partial failure, surprise removal, power cycling, fault storms, and secure-ATS enable/disable; inspect the 512-entry group-fault bookkeeping for bounds and stale references.
5. Capture the two new CI network-activity providers and `CiLogSignatureExpiryEvent`; recover schemas and correlate them with SmartScreen/SAC allow, block, offline, Defender-disabled, and upgrade cases.
6. Diff the named win32k and filesystem servicing gates in IDA/Ghidra/BinDiff, prioritizing orphan-object prevention, UMPD locking, recursive GDI reset, oplock cancellation, writable mappings, and EA copying.
7. Verify live-dump protected-process exclusions against shared memory, cloned handles, process termination, and PPL signer levels, and document any visibility tradeoff for incident response.
