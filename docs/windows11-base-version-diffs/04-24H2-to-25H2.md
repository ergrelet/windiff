# WinDiff analysis: Windows 11 core security surface — 24H2 → 25H2 (amd64)

## Scope

- Old: Windows 11 24H2 / BASE / `10.0.26100.1` for all seven binaries.
- New: Windows 11 25H2 / BASE / shared 26100 servicing line.
  `ntoskrnl.exe` and `ci.dll` report `10.0.26100.6584`; `ntdll.dll`, `cng.sys`,
  and all three win32k binaries report `10.0.26100.5074`.
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`,
  `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: same-platform enablement/servicing, GUI attack-surface migration,
  CI/PPL hardening, mitigation telemetry, DMA isolation, and inline storage crypto

This is not a new kernel platform baseline: both sides identify as build 26100.
It is also not an atomic patch comparison because the selected 25H2 files span
revisions 5074 and 6584. Findings therefore describe accumulated servicing and
enablement visible in these exact files, not changes attributable solely to the
25H2 enablement package.

## Executive summary

- The native service table is unchanged: no ntoskrnl or ntdll syscall addition,
  removal, or renumbering is reported. Win32k is different: it adds 17 entries,
  removes nine, and renumbers 1,156 on the shared 26100 line. The principal new
  surface is DirectComposition/DWM messaging, input/touchpad injection, intercept
  windows, window-station creation, and process Win32 capability policy.
- **[EDR] [vuln-research]** Code Integrity exposes unusually specific servicing
  gates for a WinTcb PPL TOCTOU, CI policy deadlock, HVCI/control-area
  synchronization, VBS policy-count bugcheck, and enterprise cached-signing-level
  handling. These names are strong hardening leads, not proof of a CVE or exact
  vulnerable interleaving.
- **[EDR]** `EtwTimLogProhibitFsctlSystemCalls` adds mitigation-specific
  telemetry. Earlier raw data already contained the FSCTL process-mitigation
  feature name, so this is best read as visibility for an existing policy rather
  than the introduction of a new policy bit.
- **[EDR] [vuln-research]** CI adds 2024 Microsoft code-signing PCA identities,
  a CA-remapping list and “default Windows CA remapping disallowed” policy,
  Trusted Launch catalog validation, WNC policy identities/audit events, and
  policy-options v2 parsing. The theme is trust-anchor migration plus policy
  correctness on the existing platform.
- **[vuln-research]** Memory management gains an explicitly named
  `Mm_OriginalPteRace` servicing gate. IOMMU state adds a first-stage paging-mode
  flag, while `PasidDomainId` is moved into the native-device variant rather than
  newly created.
- No new process-mitigation bit appears. The heap resolved-member delta repeats
  the same two semantic flags with a narrower backing type, so it is treated as
  representation churn, not a new heap mitigation.

## New syscalls

### Native services

None. `ntoskrnl.exe` remains at 475 extracted entries and ntdll at 488, with no
additions, removals, or renumbering. This is consistent with a shared 26100
kernel baseline.

### Win32k services

Seventeen entries are added to the GUI shadow table:

- **Composition and DWM:** `NtDCompositionCreateBufferCollection [4380]` creates
  a new stateful composition-resource family with handle resolution, validity,
  and rundown code in win32kbase. `NtDCompositionSendDwmLpcMessage [4407]` adds
  an explicit DWM LPC message path. **[vuln-research]** Both deserve input-size,
  handle-type, cross-process ownership, malformed-message, and teardown fuzzing.
- **Intercept-window and shell state:** `NtUserConvertToInterceptWindow [5063]`
  and `NtUserIsInterceptWindow [5292]` are backed by a new
  `CInterceptWindowProp` object that saves/restores pending display-change and
  window-action data. `NtUserCanCurrentThreadChangeForeground [5044]`,
  `NtUserEnterMoveSizeLoop [5138]`, and `NtUserSetShellSpecialWindow [5488]`
  round out the window-policy changes. **[anti-cheat] [vuln-research]** Validate
  which brokers may convert a window, property lifetime on destruction, and
  foreground-policy authorization.
- **Namespace and capability policy:** `NtUserCreateWindowStationEx [5076]`
  expands creation of a security-boundary object, while
  `NtUserSetProcessWin32Capabilities [5483]` exposes process-scoped GUI
  capability state. **[anti-cheat] [vuln-research]** Compare object attributes,
  desktop/session inheritance, AppContainer checks, and downgrade behavior with
  the older integrity-level gate.
- **Input and CoreMessaging:** `NtUserGetLatestInputMessageData [5195]`,
  `NtUserGetPointerIdForPromotion [5215]`,
  `NtUserInjectTouchpadAction [5287]`,
  `NtUserPromotePrimaryPointerToDrag [5348]`,
  `NtUserRegisterCoreMessagingEndPoint [5364]`,
  `NtUserRegisterTouchpadCapableWindow [5386]`, and
  `NtUserSetMaxTouchpadSensitivity [5466]` add input-routing and endpoint
  surface. **[anti-cheat] [vuln-research]** Synthetic input provenance,
  capability checks, device-object lifetime, and endpoint teardown are priority
  tests.
- **Power policy:** `NtUserSetAdditionalPowerThrottlingProcess [5424]` sets
  additional per-process GUI power state. This is lower security signal, but its
  process handle/access validation should match other process-setting services.

The 1,156 renumberings are service-table regeneration. Direct-syscall consumers
must update IDs; the renumbering count is not feature growth.

## New / changed security mitigations

- **FSCTL system-call prohibition telemetry:**
  `EtwTimLogProhibitFsctlSystemCalls` is new. **Fact:** the kernel now has a named
  mitigation-event producer. **Inference:** it records enforcement or audit of a
  policy that blocks selected filesystem-control system calls. The preceding
  23H2 → 24H2 raw diff removed `Feature_FsctlProcessMitigation` and
  `IoFsctlProcessMitigationEnabled`, so the 25H2 logger should not be presented as
  proof that the policy itself is new. **[EDR]** Find callers, provider/event ID,
  blocked-control-code fields, and audit-versus-enforce behavior.
- **Original-PTE race hardening:** the symbols
  `Feature_Servicing_Mm_OriginalPteRace` and `MmOriginalPteRaceFixEnabled` are
  added. **[vuln-research]** The names directly identify a guarded memory-manager
  race fix; they do not reveal the affected PTE lifecycle or exploitability.
  Patch-diff PFN original-PTE capture/restore paths and stress concurrent
  fault/unmap/protection transitions.
- **IOMMU first-stage paging:**
  `_EXT_IOMMU_S1_X64_DOMAIN_SETTINGS::Flags` consumes one reserved bit for
  `FirstStagePagingMode`. **[anti-cheat] [vuln-research]** This expands explicit
  domain-mode policy and is relevant to DMA isolation. Confirm who selects the
  mode and how invalidation/fault handling differs.
- **Heap flag artifact:** `_RTL_HP_VS_CONFIG::Flags` reports
  `PageAlignLargeAllocs` and `EnableDelayFree` as removed `ULONG` bitfields and
  added `UCHAR` bitfields, while the enclosing structure shrinks from four bytes
  to one. The semantic names are unchanged, so this is layout compaction, not two
  new mitigations.

## New security-relevant features & components (beyond mitigations)

### Code integrity, PPL, and boot trust

- `Feature_Servicing_CodeIntegrityWinTcbPplTocTou` is the strongest named
  security fix. **[EDR] [anti-cheat] [vuln-research]** It explicitly associates
  a time-of-check/time-of-use correction with WinTcb PPL handling. Reverse the
  guarded old/new path to determine which file, signer, process, or cache object
  changed between validation and use; do not infer a specific CVE from the name.
- `Feature_Servicing_CodeIntegrityPolicyDeadlock`,
  `CodeIntegrityHvciSyncControlArea`, `CodeIntegrityPolicyCountVbsBugcheck`, and
  `CodeIntegrityNtSetCachedSigningLevelEnterpriseSigned` identify targeted
  concurrency, lifetime, and verdict-caching corrections. **[EDR]
  [vuln-research]** Stress concurrent policy refresh/image mapping and cached
  signing-level changes, especially where HVCI owns a control area.
- `MicrosoftCodeSigningPCA2024` and
  `MicrosoftWindowsCodeSigningPCA2024` appear alongside
  `g_SIPolicyCARemapList` and
  `SIPolicyIsDefaultWindowsCARemappingDisallowed`. **Fact:** CI now carries new
  PCA identities and explicit CA-remapping policy. **Inference:** this supports
  migration from older signing roots while allowing policy to reject implicit
  remapping. **[EDR] [vuln-research]** Test mixed old/new chains, timestamp
  boundaries, revocation, and policies that differ on remapping.
- `CipGetTrustedLaunchPackage`, `CipIsTrustedLaunch`, and
  `KappxValidateCatalogForTrustedLaunch` add an explicit Trusted Launch package
  validation path. **[EDR] [anti-cheat]** Confirm package/catalog identity
  binding and cache invalidation across update or rename.
- `SiPolicyIDWnc*`, `CiInstrumentSignatureFailuresForWNC`,
  `CiShouldFireWncBlockEvent`, and `Feature_WNCPolicyAuditEvt` create a named WNC
  enforce/audit family. The acronym's semantics are not established by this
  dataset; the data does establish dedicated policy identities and failure
  instrumentation. **[EDR]** Recover policy files and event schemas before
  assigning a product name.
- `SIPolicyGetPolicyOptionsV2` plus new typed SI-policy reader helpers indicates
  parser/version evolution. **[vuln-research]** Fuzz primitive arrays, signer
  indices, strings, truncation, and rollback after partial reads.

### Detection and audit state

`_TOKEN_AUDIT_POLICY::PerUserPolicy` grows from 30 to 31 bytes, indicating one
additional per-user audit-policy slot, while `_SEP_AUDIT_POLICY` is reorganized.
**[EDR]** The diff does not name the new subcategory; map the index through audit
policy constants and verify token cloning/inheritance.

`EtwTiLogRevertToSelf`, introduced in the previous platform jump, disappears
while `EtwTiLogImpersonateClient` remains. That may be event consolidation into
the impersonation producer rather than a lost event. **[EDR]** Runtime tracing
must determine whether reversion remains observable and under which opcode.

### Inline storage encryption and DMA

New `_STORAGE_HW_CRYPTO_CAPABILITY`, `_STORAGE_HW_CRYPTO_DESCRIPTOR`, algorithm,
key-size, key-type, and ICE types accompany a larger
`_IO_ADAPTER_CRYPTO_KEY_DESCRIPTOR` with key namespace, key type, and parameter-
adjustment callback/context. A feature symbol names an inline NVMe crypto engine.
**[EDR] [vuln-research]** This is an expanded kernel/device contract for inline
storage encryption. Audit descriptor length/version validation, callback
lifetime, key-namespace binding, fallback behavior, and crash/hibernate paths.

`_IOMMU_DMA_DEVICE::PasidDomainId` is not genuinely new: the named field moves
from the outer device layout into the `Native` variant. Reporting it as an added
PASID feature would overstate the resolved anonymous-member delta.

### Internal feature-configuration API

Kernel and ntdll both export `RtlQueryInternalFeatureConfiguration`,
`RtlQueryAllInternalFeatureConfigurations`, and
`RtlQueryAllInternalRuntimeFeatureConfigurations`; ntdll also adds API-set
schema query exports. **[vuln-research]** These are not new syscalls, but they
make internal feature state more directly consumable by components. Validate
caller contracts, buffer sizing, and whether sensitive staged-feature state is
filtered across trust boundaries.

## New attack surface (routines, callbacks, object types)

- The 17 win32k entries are the principal new user-reachable surface. Prioritize
  DWM LPC messages, composition buffer collections, window-station creation,
  process capability setting, touchpad injection, and CoreMessaging endpoint
  registration.
- `CBufferCollectionResource` introduces a handle-backed composition object with
  validity and rundown transitions. **[vuln-research]** Cross-channel ownership,
  duplicate handles, invalidation during capture, and process teardown are
  natural state-machine fuzz targets.
- `CInterceptWindowProp` stores system-operation/window-action data and pending
  display changes on a window. **[vuln-research]** Test replacement, window
  destruction, owner-thread exit, and asynchronous DWM callbacks.
- CI's typed policy readers and Trusted Launch catalog parser handle attacker-
  influenced signed artifacts even when cryptographic authorization is expected;
  parsing and cache binding remain useful research surface.
- CNG adds no export or syscall and only 29 symbols; its 113 added/115 removed
  modules largely reflect SymCrypt object-path/build provenance churn. The raw
  diff does not justify claiming a new CNG algorithm or provider.

## Notable structure changes

- `_SYSTEM_INFORMATION_CLASS` replaces `SystemSecureSecretsInformation [0xf2]`
  with `SystemSecureCoreInformation [0xf2]` and adds processor-feature bitmap,
  basic-process, and handle-count selectors. Reuse of the same value indicates
  contract replacement/rename, not simultaneous availability of both classes.
- `_IOMMU_DMA_DEVICE` is reorganized around native/SVM state, while first-stage
  domain mode becomes explicit as described above. Layout consumers must use
  symbols for the exact serviced build.
- `_KNODE::Flags::SmtSetsPresent` consumes a spare bit and appears in both kernel
  and ntdll type views. This is scheduler/topology state, not a mitigation by
  itself, but it may steer SMT-aware placement or isolation decisions.
- `_RTL_HP_VS_CONFIG` compacts from four bytes to one without changing its two
  named policy bits. This is an ABI warning for private-structure tooling.

## Removed / deprecated

- Win32k removes `NtUserCheckAccessForIntegrityLevel` while adding
  `NtUserSetProcessWin32Capabilities`; it removes
  `NtUserCanBrokerForceForeground` while adding
  `NtUserCanCurrentThreadChangeForeground`; and it removes suppression/internal
  move-size calls while adding the intercept-window and enter-move-size model.
  These pairings suggest policy/interface migration, not disappearance of the
  underlying behavior. **[anti-cheat] [vuln-research]** Look for compatibility
  thunks and compare authorization before and after migration.
- `NtCompositionInputThread`, precision-touchpad registration, fallback-
  foreground, and mouse-rate-limit timer entries also disappear. Their backing
  logic may have moved behind CoreMessaging/touchpad-capable-window APIs.
- `EtwTiLogRevertToSelf` and `VslQueryTrustedAppRuntimeInformation` disappear as
  symbols. Neither removal proves the event or trusted-app capability was
  eliminated; both may be consolidated or inlined on the serviced baseline.

## Research leads

1. Build an old/new win32k syscall map and fuzz the migrated pairs, especially
   integrity-level versus process-capability checks and suppress-action versus
   intercept-window state.
2. Reverse `NtDCompositionSendDwmLpcMessage` and buffer-collection object methods;
   recover message formats, caller restrictions, handle ownership, and rundown.
3. Reconstruct the WinTcb PPL TOCTOU fix from the feature gate and test the
   validation/use interval without assigning an unsupported vulnerability ID.
4. Stress CI policy refresh, HVCI control-area synchronization, cached enterprise
   signing levels, and policy-count transitions under concurrent image loads.
5. Validate the 2024 PCA/remapping policy matrix with old/new roots, timestamped
   signatures, revoked chains, supplemental policies, and offline boot.
6. Locate callers of `EtwTimLogProhibitFsctlSystemCalls` and verify coverage,
   payload, audit/enforce distinction, and whether reversion from impersonation
   remains observable after the TI producer removal.
7. Patch-diff the original-PTE race gate and build a concurrency harness around
   the affected fault/unmap/protection path.
8. Fuzz hardware-crypto descriptor negotiation and IOMMU first-stage mode across
   device start, reset, surprise removal, hibernate, and fault recovery.

## Evidence and limitations

- “Added” means present in the selected serviced 26100 file and absent from
  26100.1. Because the new database mixes revisions 5074 and 6584, this is an
  accumulated servicing comparison, not an atomic 25H2 image diff.
- Feature-gate names can identify the engineering area of a correction but do
  not prove exploitability, default enablement, or a specific CVE.
- No new process-mitigation member was resolved. Anonymous type-ID churn is
  hidden, and the heap flag type-width change is explicitly discounted.
- Win32k has no reconstructed types on either side of this comparison, so its
  syscall/symbol evidence cannot be paired with type-layout changes here.
- Syscall renumbering is normal table regeneration. Symbol and module churn may
  also reflect compiler, link, or build-path changes; CNG is the clearest case.
