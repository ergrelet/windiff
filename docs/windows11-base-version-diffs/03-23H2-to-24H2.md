# WinDiff analysis: Windows 11 core security surface — 23H2 → 24H2 (amd64)

## Scope

- Old: Windows 11 23H2 / BASE / serviced 22621 binaries. `ntoskrnl.exe`,
  `ntdll.dll`, and the win32k binaries report `10.0.22621.2428`; `ci.dll`
  reports `10.0.22621.2361`; `cng.sys` reports `10.0.22621.1992`.
- New: Windows 11 24H2 / BASE / `10.0.26100.1` for all seven binaries.
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`,
  `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, `cng.sys`
- Focus: new native and GUI services, threat telemetry, VBS/driver isolation,
  call-target and object hardening, and code-integrity policy

This is a full 22621 → 26100 platform jump. The old BASE database is not one
atomic 22621 image: Winbindex selected serviced files at three revisions. Claims
below therefore describe the selected PE/PDB pairs, not necessarily a feature's
first public appearance in the 23H2 or 24H2 marketing release.

## Executive summary

- **[EDR] [anti-cheat]** Threat Intelligence gains dedicated producers for
  impersonation, reversion, and syscall use: `EtwTiLogImpersonateClient`,
  `EtwTiLogRevertToSelf`, and `EtwTiLogSyscallUsage`. These close visibility
  gaps around token-context transitions and native-service activity, subject to
  provider enablement and event filtering.
- **[vuln-research]** Three native services are corroborated by both the kernel
  table and ntdll stubs: `NtAlertMultipleThreadByThreadId`,
  `NtAlertThreadByThreadIdEx`, and `NtSetEventEx`. Win32k adds 31 GUI/GDI/DXG
  entries, including synthetic-input v2, capability-setting, UMPD-sandbox,
  composition, display-mux, and window-action operations.
- **[EDR] [anti-cheat] [vuln-research]** A new driver-proxy subsystem is visible
  through six kernel exports, a `_DRIVER_EXTENSION` pointer, three implementation
  modules, and secure-kernel service IDs for creating, registering, and swapping
  endpoint-wrapper sections. This is consistent with moving selected driver
  interactions behind a VBS-enforced proxy boundary.
- **[EDR] [anti-cheat]** Trusted-app state becomes explicit through
  `_KPROCESS::SecureState::Flags::TrustedApp`,
  `SystemTrustedAppsRuntimeInformation`, and VSL query code. Object types also
  gain mandatory-label and trust-constraint masks.
- **[EDR] [vuln-research]** `ci.dll` undergoes a large policy-engine refactor:
  SI-policy state/serialization modules, HVCI image and hotpatch validation,
  revocation-list synchronization with SKCI, VBS-policy diagnostics, origin
  claims, and NightsWatch/Smart App Control policy identities arrive together.
- XFG is explicitly retired rather than expanded: the process bits become
  `XtendedControlFlowGuard_Deprecated` and the policy enum becomes
  `PS_MITIGATION_OPTION_RESERVED_WAS_XFG`. In contrast, new SCP/CFG-page and
  `RtlValidateUserCallTarget` plumbing appears to strengthen a different
  call-target-validation path.

## New syscalls

### Native services

- **`NtAlertMultipleThreadByThreadId` [110]** — alerts multiple target threads
  by thread ID. The paired ntdll `Nt*`/`Zw*` exports and syscall records confirm
  a new user/native boundary. The batch form expands validation and concurrency
  cases beyond the older single-thread alert path. **[vuln-research]** Confirm
  handle/ID lifetime, partial-success semantics, access checks, and races with
  termination.
- **`NtAlertThreadByThreadIdEx` [114]** — an extended form of thread alerting,
  again paired in ntdll. The `Ex` suffix implies new flags or output semantics;
  its exact contract is not recoverable from names alone. **[vuln-research]**
  Reverse the kernel handler and compare its probing and authorization with the
  original service.
- **`NtSetEventEx` [417]** — an extended event-signaling operation with a paired
  ntdll stub. It adds synchronization-object surface and should be checked for
  handle-type, access-mask, and state-transition differences from `NtSetEvent`.
  **[vuln-research]**

The kernel raw diff labels six additions, but the other three are not confirmed
new services: `xHalIommuFinalizeDeviceReset` is a HAL routine,
`ext_ms_win_ntos_tm_l1_1_0_NtRenameTransactionManager` is an API-set-style
forwarder name, and `NtSetLowWaitHighEventPair` has no matching new ntdll stub.
The corresponding raw removals also mix old `Nt*` names with `Bvga*`/`xHal*`
symbols. They are retained in the appendix counts but treated as extraction or
classification artifacts, not new user-mode entry points.

### Win32k services

The 31 new win32k table entries fall into coherent groups:

- **Capability and sandbox policy:** `NtGdiDisableUMPDSandboxing [4722]`,
  `NtUserSetUserObjectCapability [5492]`, and
  `NtUserSetWindowMessageCapability [5502]` are backed by new
  win32kbase/full routines. The latter two appear to attach capability policy to
  USER objects and window-message delivery; the GDI call exposes an explicit
  sandbox transition for user-mode printer drivers. **[anti-cheat]
  [vuln-research]** Authorization and one-way/rollback semantics are the
  priority: names do not prove these calls are available to an ordinary process.
- **Synthetic input and core messaging:**
  `NtUserCreateSyntheticPointerDevice2 [5072]`,
  `NtUserDrainThreadCoreMessagingCompletions2 [5104]`,
  `NtUserInitThreadCoreMessagingIocp2 [5270]`, and
  `NtUserRegisterPrecisionTouchpadWindow [5370]` expand stateful input and IOCP
  paths. **[anti-cheat] [vuln-research]** The v2 interfaces likely add metadata
  or capability checks; validate size/version fields and teardown races.
- **Composition, GPU, and display:**
  `NtConfirmCompositionSurfaceIndependentFlipEntry [4369]`,
  `NtDCompositionSyncWait [4413]`, the three-stage
  `NtDxgkDisplayMuxSwitchPrepare/Execute/Finish [4432/4430/4431]` family,
  `NtDxgkGetNativeFenceLogDetail [4438]`, `NtDxgkIsFeatureEnabled [4442]`,
  `NtGdiGetPhysicalMonitorFromTarget [4819]`, and `NtGdiInit2 [4839]` add
  GPU/display object and synchronization surface. **[vuln-research]** Fence-log
  output, mux state transitions, and init/version parsing are the highest-value
  review points.
- **Window and shell state:** `NtUserApplyWindowAction [5030]`,
  `NtUserDwmWindowNotificationsEnabled [5116]`,
  `NtUserEnableWindowShellWindowManagementBehavior [5133]`,
  `NtUserGetDwmCursorShape [5170]`, `NtUserGetProp2 [5219]`,
  `NtUserGetSuppressedWindowActions [5233]`,
  `NtUserInternalStartMoveSize [5285]`,
  `NtUserIsWindowDisplayChangeSuppressed [5295]`,
  `NtUserRaiseLowerShellWindow [5348]`,
  `NtUserRegisterCloakedNotification [5357]`,
  `NtUserSetCoveredWindowStates [5429]`, `NtUserSetProp2 [5477]`,
  `NtUserShellForegroundBoostProcess [5507]`,
  `NtUserSuppressWindowActions [5525]`, and
  `NtUserSuppressWindowDisplayChange [5526]` cover window action, property,
  notification, suppression, and foreground state. These are mostly policy and
  lifecycle operations, but shared window handles and asynchronous DWM
  interactions make stale-object and authorization testing worthwhile.
  **[anti-cheat] [vuln-research]**

The 1,149 win32k renumberings are table regeneration, not 1,149 features. They
matter to direct-syscall tooling but are not interpreted as attack-surface growth.

## New / changed security mitigations

- **`_KPROCESS::SecureState::Flags::TrustedApp`** replaces one unused bit.
  `SystemTrustedAppsRuntimeInformation` and `VslQueryTrustedAppRuntimeInformation`
  form a companion query path, while `PsTrustedAppsRuntimeDll` remains a named
  runtime-DLL class. **Fact:** kernel process state now distinguishes trusted
  apps. **Inference:** the bit likely selects VBS/trusted-app scheduling or
  execution behavior. **[EDR] [anti-cheat]** Reverse writers of the bit and test
  whether it affects handle access, memory operations, or telemetry.
- **SCP/CFG call-target validation** appears as `_RTL_SCP_CFG_PAGE_TYPE`,
  `PsInitializeScpCfgPages`, `MiMapImageScpCfgPages`,
  `KscpCfgHandleInvalidCallTarget`, and new secure services for initializing
  KSCP functions and mapping kernel SCP state. Ntdll adds
  `RtlValidateUserCallTarget` and `RtlpScpCfgNtdllExports`. **Fact:** a new set of
  CFG-page and invalid-target handlers spans memory management, process setup,
  ntdll, and the secure kernel. **Inference:** this is a hardened call-target
  validation channel; the acronym's exact product meaning and default coverage
  need disassembly confirmation. **[anti-cheat] [vuln-research]**
- **XFG deprecation:** `_EPROCESS::MitigationFlags2Values` renames both XFG bits
  to `XtendedControlFlowGuard_Deprecated` and
  `AuditXtendedControlFlowGuard_Deprecated`; `_PS_MITIGATION_OPTION` changes the
  corresponding value to `RESERVED_WAS_XFG`. This is explicit retirement, not a
  new mitigation. Determine whether callers are rejected, ignored, or mapped to
  another guard policy. **[vuln-research]**
- **Allocator zeroing policy:** `_MI_SLAB_ALLOCATOR_CONTEXT::Flags` replaces
  `ZeroedPages` with separate `PreferZeroedPages` and `ZeroOnFree` bits, plus a
  two-bit `LargePageIndex`. **[EDR] [vuln-research]** This gives the allocator
  explicit confidentiality-oriented state, although the diff does not show
  which pools enable it by default. Trace flag initialization and reuse paths.
- The new Csan/KCSAN and volatile ASan helper families are sanitizer and Driver
  Verifier instrumentation support. They improve bug discovery when enabled but
  are not evidence that production workloads receive a new always-on mitigation.

## New security-relevant features & components (beyond mitigations)

### Threat Intelligence telemetry

- **`EtwTiLogImpersonateClient` / `EtwTiLogRevertToSelf`** are paired with new
  token-identity capture/serialization helpers and three
  `THREATINT_PROCESS_IMPERSONATION_*` states. **[EDR] [anti-cheat]** This strongly
  indicates first-class events for entering, changing, and leaving an
  impersonation context. Validate provider GUID, actor/target identity fields,
  stack capture, and behavior inside silos and protected processes.
- **`EtwTiLogSyscallUsage`** adds a generic syscall-usage producer. **[EDR]**
  Whether it covers all services or only selected sensitive calls is not shown;
  inspect callers and runtime keywords before treating it as comprehensive
  syscall telemetry.

### Driver proxy, VBS, and DMA isolation

`IoCreateDriverProxyExtension`, `IoRegisterDriverProxyEndpoints`,
`IoGetDriverProxyFeatures`, endpoint-wrapper helpers, and a new
`_DRIVER_EXTENSION::DriverProxyExtension` establish a driver-facing proxy API.
The `_SKSERVICE` enum adds secure operations for endpoint-wrapper section
creation/registration and endpoint swapping. `_IOMMU_ATS_SETTING` and
`_IOMMU_PASID_SETTING` also become named types, with a new secure-service entry
for configuring secure ATS devices. **[EDR] [anti-cheat] [vuln-research]** This
is consistent with stronger isolation for device/driver communication and DMA,
but the trust boundary must be confirmed from the proxy call flow. Audit endpoint
registration, shared-section validation, swap/rundown, PASID ownership, and
IOMMU-fault recovery.

### Object-manager trust constraints

`_OBJECT_TYPE` grows `SeMandatoryLabelMask` and `SeTrustConstraintMask`, and
`_OBJECT_TYPE_INITIALIZER` gains `SeTrustConstraintMaskPresent`. **[EDR]
[anti-cheat] [vuln-research]** The data directly shows per-object-type trust
metadata. It likely allows the Security Reference Monitor to apply object-type-
specific trust-label constraints in addition to mandatory integrity, but the
affected object types and access-check path require reversing.

### Code integrity and boot trust

- New `sipolicyapplicationsettings`, `sipolicyserialization`,
  `sipolicysigning`, `sipolicystate`, `sipolicyumci`, and `sipolicyvbs` modules
  accompany `SIPolicyNewState`, add/remove/commit operations, signer/scenario
  iteration, VBS queries, and serialized-policy sizing. **Fact:** policy handling
  moves toward an explicit state object and split parser/serialization model.
  **Inference:** the refactor supports more atomic multi-policy refresh and
  clearer VBS/UMCI separation. **[EDR] [vuln-research]** Test refresh rollback,
  signer precedence, malformed serialized input, and concurrent readers.
- `CiHvciFindHotPatchMetadataOffset`, `CiHvciIsImageDisallowed`,
  `CiHvciUnlockImage`, and `CipShouldImageBeForwardedToHvci` expand the boundary
  between ordinary CI and HVCI. `CipUpdateRevocationListInSKCI` explicitly pairs
  revocation state with secure-kernel CI. **[EDR] [vuln-research]** Review image
  lifetime across validation/unlock and revocation refresh.
- `SiPolicyIDNightsWatch*`, Picroot-exception policy IDs, Smart App Control mode
  instrumentation, and Defender-triggered mode transitions expose a larger SAC
  policy-state machine. The internal names support that association; they do not
  establish defaults or user-visible branding. **[EDR]**
- `SystemCodeIntegritySignedPoliciesFullInformation` adds a system-information
  query class for fuller signed-policy state. Access control, output stability,
  and whether sensitive policy details are redacted should be tested.

### RCU/SRCU lifetime infrastructure

Kernel exports add RCU and sleepable-RCU read-side, synchronize, allocation, and
free operations; ntdll adds a parallel `RtlRcu*` family. Per-CPU RCU state and
work-item types appear in recovered types. **[vuln-research]** This is general
concurrency infrastructure, not a mitigation by itself, but migrations from
locks/reference counts to grace-period reclamation are prime UAF patch-diff
targets. Identify first consumers and stress process/driver teardown paths.

## New attack surface (routines, callbacks, object types)

- The three confirmed native services and 31 win32k services are the main new
  user-reachable surface. The thread-alert batch/extended paths, synthetic input,
  DWM/DirectComposition synchronization, display-mux state machine, capability
  setters, and UMPD-sandbox transition deserve priority fuzzing.
- `PsRegisterProcessAvailableCpusChangeNotification` and
  `PsRegisterSystemAvailableCpusChangeNotification` add driver callback
  registration, paired with unregister and query exports. **[vuln-research]**
  Check callback lifetime across CPU partition/process teardown and hot-add.
- The driver-proxy exports expose a new kernel-driver contract. They are not
  direct user-mode calls, but endpoint metadata and wrapper sections may carry
  less-trusted data across an isolation boundary.
- CNG gains per-silo configuration lifecycle (`CngSiloCreateNotify`,
  `CngSiloTerminateNotify`) and an entropy-accumulator callback hook. **[EDR]
  [vuln-research]** Confirm configuration isolation and entropy-callback trust;
  no CNG export or syscall was added.

## Notable structure changes

- `_SYSTEM_INFORMATION_CLASS` grows nine functional entries, including signed
  CI policy, secure secrets, trusted-app runtime, bad-page, and resource-deadlock
  information. These are query selectors, not nine new syscalls; they expand
  existing `NtQuerySystemInformation` parsing and authorization surface.
- `_TEB`, `_TEB32`, and `_TEB64` grow dedicated heap-FLS, RNG, scheduler-shared,
  heap-walk, primary-group-affinity, and RCU state. Ntdll exports new TLS/FLS and
  RCU helpers, providing strong companion evidence for the user-runtime change.
- `_WMI_LOGGER_CONTEXT` grows an ETW APC pool and context-register logging state.
  This is telemetry infrastructure that may support the new syscall/context
  visibility; it does not by itself identify which events are enabled.
- `_MI_SLAB_ALLOCATOR_CONTEXT`, `_MI_PFN_FLAGS*`, and many core memory-manager
  types change substantially. The platform jump is too broad to interpret every
  layout delta as hardening; only named behavioral fields are elevated above.

## Removed / deprecated

- XFG policy state is explicitly deprecated as described above.
- Win32k removes 13 table entries, including the original pointer-device
  injection calls, precision-touchpad configuration calls, several DWM-channel
  operations, and run-thread helpers. New v2/core-messaging and window-action
  entries suggest migration rather than simple surface deletion. **[vuln-research]**
  Check whether compatibility thunks retain the old parsers.
- `ci.dll` removes older AC-policy and monolithic SI-policy helpers while adding
  the state/serialization design. Symbol absence is evidence of refactoring, not
  proof that the underlying policy capability disappeared.
- The apparent loss of all 428 `win32k.sys` types is an extraction discontinuity:
  24H2 has no reconstructed win32k types in this database. It must not be read as
  428 real type removals.

## Research leads

1. Capture the three new TI event families at runtime and map provider keyword,
   payload, protected-process/silo coverage, suppression, and event-loss behavior.
2. Reverse and fuzz the three confirmed native handlers, especially thread-ID
   lifetime and partial failure in `NtAlertMultipleThreadByThreadId`.
3. Build a capability matrix for the 31 new GUI services: caller integrity,
   AppContainer capability, session/desktop, win32k-lockdown, and broker paths.
4. Trace driver-proxy endpoint registration and secure-kernel section operations
   end to end; stress endpoint swap, driver unload, process exit, and malformed
   shared metadata.
5. Identify which object types set `SeTrustConstraintMaskPresent`, then compare
   old/new access-check decisions for trust labels and mandatory integrity.
6. Model SI-policy refresh as a transaction and test parser failure, rollback,
   concurrent validation, revocation update, and HVCI handoff.
7. Map SCP/CFG page construction and invalid-target dispatch across ntdll, the
   memory manager, process initialization, and the secure kernel.
8. Find initial RCU/SRCU consumers and patch-diff their old reclamation paths for
   races that motivated the conversion.

## Evidence and limitations

- “Added” means present in the selected 26100.1 PE/PDB-derived database and
  absent from its selected serviced 22621 counterpart. It does not prove default
  enablement, first shipment in a marketing release, or low-privilege reachability.
- Native syscalls are called confirmed only when the kernel entry and companion
  ntdll stub/export agree. Win32k table entries are directly extracted, but this
  dataset does not include `win32u.dll` for user-stub pairing.
- Anonymous type IDs are ignored; the report relies on named type modifications
  and the resolver's parent/member changes. The XFG, trusted-app, and allocator
  flag claims come from those resolved members.
- Large symbol/module churn is expected across a 22621 → 26100 rebuild. Names
  establish presence and support subsystem hypotheses; semantics and access
  controls still require disassembly or runtime validation.
