# WinDiff analysis: Windows 11 core security surface — 25H2 → 26H1 KB5077179 (amd64)

## Scope

- Old: Windows 11 25H2 / BASE / shared 26100 servicing line.
  `ntoskrnl.exe` and `ci.dll` report `10.0.26100.6584`; the other five files
  report `10.0.26100.5074`.
- New: Windows 11 26H1 / KB5077179 / OS build 28000.1575. Microsoft lists this
  February 10, 2026 B release as the first cumulative update in the
  [26H1 release history](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information).
- Architecture: `amd64`
- Binaries compared: `ntoskrnl.exe`, `ntdll.dll`, `win32k.sys`,
  `win32kbase.sys`, `win32kfull.sys`, `ci.dll`, and `cng.sys`
- Focus: native and GUI attack surface, driver/callback isolation, memory
  hardening, Code Integrity and boot trust, and post-quantum cryptography

The configured 26H1 BASE/ISO artifacts are unavailable from Winbindex, so this
report deliberately uses the earliest chronological 26H1 cumulative update
rather than silently ending the series. This is a mixed-scope comparison:
serviced 25H2 BASE files against one 26H1 update, not BASE against BASE and not
an isolated analysis of KB5077179. The kernel reports `10.0.28000.1575` and
ntdll reports `10.0.28000.1516`; version metadata is blank for the five other
26H1 databases even though their files were recovered from the KB5077179 tuple.

## Executive summary

- This is a full 26100 → 28000 platform jump. One native service is corroborated
  across kernel and ntdll: `NtManageWobTicket`, accompanied by priority/QoS query
  helpers and a work-on-behalf information class. A kernel-only
  `NtCompleteConnectPort` row is not counted as new because ntdll does not add a
  matching stub and the API predates 26H1.
- **[EDR] [anti-cheat] [vuln-research]** The kernel adds a callback-registration
  tree, validation prologue/epilogue, and an unload-time registration check. The
  names support an inference that 26H1 tracks callbacks owned by drivers and
  detects stale registrations during unload—a valuable lifetime-hardening lead,
  not a new public callback API.
- **[EDR] [vuln-research]** Driver isolation and device containment expand through
  660 `DifNt*`/`DifZw*` wrappers, 166 `pXdv*` and 166 `Verifier*` additions,
  driver-proxy endpoint hot-swap/version exports, and IOMMU fault callback state.
  Much of the very large symbol count is interposition/verification machinery,
  not 5,252 independent features.
- **[EDR] [vuln-research]** CI gains hotpatch-specific policy parsing and target
  authorization, Trusted Launch host identities, new policy IDs, and ML-DSA
  signature verification. CNG adds public `BCryptEncapsulate` and
  `BCryptDecapsulate` exports backed by ML-KEM, plus internal ML-DSA support.
- Win32k adds eleven and removes ten services. The new surface concentrates on
  remote DirectComposition textures, user-mode GPU submission queues/ring
  resizing, key-event inspection, and job UI-restriction management. The 1,185
  renumberings are table regeneration, not equivalent to new functionality.
- No new named `EtwTi*`/`EtwTim*` producer or process-mitigation bit is visible.
  The security signal instead lies in callback lifetime, trust policy, driver
  containment, cryptography, and memory-manager representation changes.

## New syscalls

### Native services

- **`NtManageWobTicket` [284]** — confirmed by the ntdll export/stub family
  (`NtManageWobTicket`/`ZwManageWobTicket`) and kernel handler. Nearby
  `RtlQueryPriorityForWobTicket`, `RtlQueryQosForWobTicket`,
  `PspQueryWobTicket*`, and `_WOB_INFORMATION_CLASS` establish a work-on-behalf
  ticket control plane for priority and QoS. **Inference:** the service manages
  scheduler/resource-accounting attributes carried by work performed for
  another party; the exact operations and authorization model require reversing.
  **[EDR] [anti-cheat] [vuln-research]** Validate ticket provenance, handle/type
  checks, information-class buffer lengths, cross-process use, inheritance, and
  whether policy changes affect attribution or throttling.
- **`NtCompleteConnectPort` [162]** — reported only by the kernel extractor.
  Ntdll adds no matching stub, and this is an existing LPC service name. It is
  therefore an extraction/table-attribution asymmetry, not evidence of a new
  26H1 syscall.

Kernel and ntdll report 198 and 205 renumbered rows respectively. Direct-syscall
consumers must use the exact 28000 tables, but the renumbering counts are not an
attack-surface metric.

### Win32k services

Eleven GUI services are added:

- **Remote composition textures:** `NtDCompositionCreateRemoteTexture [4383]`,
  `NtDCompositionOpenRemoteTexture [4403]`, and
  `NtDCompositionReleaseRemoteTexture [4408]` form a handle-backed, cross-owner
  resource lifecycle. **[vuln-research]** Test descriptor sizes, duplicate/open
  authorization, producer/consumer teardown, device loss, and release races.
- **GPU submission:** `NtDxgkCreateHwQueueForUserModeSubmission [4429]`,
  `NtDxgkDDisplayEnum2 [4432]`, and `NtDxgkResizeRingBuffer [4455]` expand the
  user/kernel graphics contract around hardware queues, display enumeration,
  and mutable ring storage. **[anti-cheat] [vuln-research]** Prioritize integer
  sizing, mapping lifetime, queue ownership, synchronization, and resize while
  commands are in flight.
- **GDI transfer state:** `NtGdiIsDcInXfer [4848]` exposes whether a device
  context is in a transfer operation. New `XFERDCOBJ` begin/end helpers and a
  container-compatibility feature suggest a revised DC-transfer state machine.
  **[vuln-research]** Check nested transitions and cleanup on exceptions.
- **Input visibility:** `NtUserGetKeyEventInfo [5192]` and
  `NtUserGetKeyboardInputThreadId [5194]` expose key-event and routing metadata.
  **[EDR] [anti-cheat] [vuln-research]** Recover access/session/desktop checks and
  determine whether callers can observe input owned by a higher-trust process.
- **Job UI policy:** `NtUserGrantJobUIRestrictionException [5263]` and
  `NtUserSetJobUILimits [5465]` add an exception path and direct mutation of
  Win32 job limits. **[anti-cheat] [vuln-research]** Verify job-handle rights,
  caller capability, inheritance, nested-job behavior, and exception revocation.

## New / changed security mitigations

No new named process-mitigation bit is resolved. Three lower-level hardening
changes are nevertheless notable:

- **Callback lifetime validation:** `KeCallbackValidationPrologue`,
  `KeCallbackValidationEpilogue`, `KeInsertCallbackRegistrationEntry`,
  `KeRemoveCallbackRegistrationEntry`, and
  `KeCheckCallbackRegistrationsOnDriverUnload` maintain a callback-registration
  tree under a dedicated lock. **Inference:** registrations are attributed to
  driver image lifetime so unload cannot leave a callable stale pointer.
  **[EDR] [anti-cheat] [vuln-research]** Identify covered callback families,
  whether failure blocks unload or bugchecks, and any callback APIs that bypass
  the tree.
- **Nonpaged-pool PFN tagging:** `_MI_ACTIVE_PFN::Leaf` and `::PageTable` consume
  four spare bits for `NonPagedBuddyTag`; `_MI_NO_STEAL_NON_PAGED_POOL_*` state
  and a new `_EXP_POOL*` manager family accompany it. **Inference:** this adds
  provenance/accounting to buddy-managed nonpaged pages during a substantial
  pool implementation rewrite. It may improve corruption detection or prevent
  inappropriate page stealing, but the symbols do not prove an exploit
  mitigation. **[vuln-research]** Trace allocation/free validation and tag
  mismatch handling.
- **ALPC message lifetime:** `_KALPC_MESSAGE::u1::s1` adds the one-bit
  `CommunicationInfoReference` field. This explicitly records ownership of a
  communication-info reference and is consistent with double-release/UAF
  hardening. **[EDR] [vuln-research]** Stress cancel, disconnect,
  impersonation, timeout, and port teardown paths to determine when the bit is
  set and consumed.

The 25H2 `Feature_Servicing_Mm_OriginalPteRace` gate and
`MmOriginalPteRaceFixEnabled` names disappear. That is consistent with a
servicing fix being folded into the newer baseline; it is not evidence that the
fix was reverted.

## New security-relevant features & components (beyond mitigations)

### Driver isolation, verifier interposition, and DMA faults

The new `DifNt*`/`DifZw*`, `pXdv*`, and `Verifier*` families mirror large parts
of the native and driver-facing API surface. **Fact:** the wrappers and
verification entry points are present. **Inference:** DIF/XDV is an expanded
driver-isolation or verifier interposition layer that mediates selected kernel
calls for proxied or constrained drivers. New
`IoGetDriverProxyExtensionVersion`, `IoHotSwapDriverProxyEndpoints`,
`MiConfigureDriverProxyState`, and `VslDriverProxyCreateStateFromImage` connect
that layer to the VBS-oriented driver-proxy work first observed in 24H2.
**[EDR] [anti-cheat] [vuln-research]** Recover dispatch selection, trust policy,
argument marshalling, wrapper parity, and fallback when VBS/HVCI is absent.

`HalDmaRegisterFaultCallback`, IOMMU registration helpers,
`_IOMMU_DMA_DEVICE_FAULT_POLICY`, and the change from an integer native
`SourceId` to an `_EXT_IOMMU_OUTPUT_MAPPING*` add structured device-fault
attribution and notification. The simultaneous removal of `PasidDomainId` from
the native variant should not be read as PASID support disappearing; the device
model has been reorganized. **[anti-cheat] [vuln-research]** Test callback
lifetime, fault storms, device removal/reset, source-ID aliasing, and policy
behavior before a driver has registered its handler.

### Code Integrity, hotpatch, and boot trust

- `SIPolicyParseHotpatchSettings`, `SIPolicyDoesHotpatchExistForTarget`, and
  `SIPolicyDoesObjectSatisfyHotpatchRule` add explicit hotpatch authorization to
  CI policy, while kernel image-loading code gains sequence/region and undo-page
  handling. **[EDR] [vuln-research]** Validate target identity, patch sequence,
  rollback, policy refresh, and file/cache binding. Their presence is not proof
  that the 26H1 product exposes hotpatching on every edition or channel.
- `Feature_TrustedLaunchHosts`, `CipGetTrustedLaunchUserSidString`, and
  `Feature_TrustedLaunchWithDevModeAndTestSigning` introduce host identity and
  an explicit development/test-signing branch into Trusted Launch policy.
  **[EDR] [anti-cheat]** Determine how host SIDs are derived and protected, and
  ensure development policy cannot bleed into production trust decisions.
- `SiPolicyIDEndpointSec` and the `SiPolicyIDIVAS*` family establish additional
  named system policies. The dataset does not define the IVAS acronym, so product
  semantics should be recovered from policy artifacts rather than guessed.
- CI adds `HashpVerifyMldsaSignature` and SymCrypt ML-DSA implementation modules.
  **[EDR] [vuln-research]** This shows post-quantum signature verification is
  available in the CI binary; call-graph and policy analysis must establish
  which signed objects may use it and whether hybrid/classical signatures remain
  mandatory.

### Post-quantum cryptography

`cng.sys` publicly exports `BCryptEncapsulate` and `BCryptDecapsulate` and adds
KEM provider operations backed by ML-KEM-512/768/1024. It also contains ML-DSA
44/65/87 key generation, signing, verification, import/export, and self-test
families. **[EDR] [vuln-research]** This is genuine cryptographic capability
growth, unlike the CNG build-path churn in 25H2. Review provider/property
validation, private-key zeroization, implicit-rejection behavior, decapsulation
failure timing, and policy/FIPS selection. Internal ML-DSA symbols do not by
themselves establish a new public kernel export for signing.

### Token, boot-layer, and platform trust state

`Feature_AdminlessElevatedToken`, `SeDuplicateTokenWithPredictedClaims`,
`PsSwapImpersonationToken`, and capability-based impersonation checks indicate
continued token/impersonation policy work. The removal of
`g_ImpersonationTokenAllowedList` may represent consolidation into capabilities,
but runtime policy must confirm that. **[EDR] [anti-cheat] [vuln-research]** Map
claim prediction and capability evaluation across token duplication and ALPC
impersonation.

New boot-layer exports and `_BACKING_LAYER_INFORMATION`, CIM, RAM-disk, VHD, and
VSMB layer types expose a generalized layered-boot storage model. Alongside
`Feature_SrtmAntiRollback`, `Feature_PlutonDynamicUpgrade`, and
`_KPROCESS_SECURE_STATE`, this broadens the pre-OS/VBS trust surface.
**[EDR] [vuln-research]** Audit layer path/descriptor parsing, mount ordering,
rollback state, and trust binding between boot artifacts and the running image.

## New attack surface (routines, callbacks, object types)

- The eleven win32k services are the clearest new user-reachable surface. Remote
  texture lifetime, ring-buffer resize, keyboard metadata, and job UI exceptions
  should lead fuzzing and access-control review.
- `NtManageWobTicket` adds a native information-class parser tied to scheduling
  and QoS state. Cross-process ticket use and confused-deputy behavior are more
  important than syscall-number fuzzing alone.
- `ObCloseHandleWithResult` plus `_OBJECT_CLOSE_RESULT` makes close outcome/state
  explicit to kernel consumers. This may improve cleanup correctness but also
  creates new branches around already-closed, protected, or teardown-racing
  objects. **[vuln-research]** Locate callers and compare refcount behavior.
- The new pool-manager, secure-pool, lookaside-manager, and PFN-tag types represent
  substantial allocator churn. **[vuln-research]** Patch-diff free-list,
  compaction, rebalancing, weak-reference, and secure-pool transitions before
  treating the rewrite as purely performance work.
- CI hotpatch policy and CNG KEM key import/export parse structured,
  attacker-influenced data even when callers are privileged. Length/version,
  integer arithmetic, rollback, and partial-initialization paths are priority
  targets.

## Notable structure changes

- `_IOMMU_DMA_DEVICE::Native::SourceId` changes from `ULONGLONG` to an
  `_EXT_IOMMU_OUTPUT_MAPPING*`, and the old inline `PasidDomainId` disappears.
  Private-structure tooling must follow symbols for the exact build.
- `_CONTROL_AREA::u2::e2` replaces seven inline image-section fields with a named
  `_MMSECTION_FLAGS2 Flags` member. This is representation factoring, not the
  disappearance of relocation, strong-code, or image-active policy.
- `_KALPC_MESSAGE::CommunicationInfoReference` and the two
  `_MI_ACTIVE_PFN::NonPagedBuddyTag` additions are the resolved anonymous-member
  changes with the clearest security/lifetime meaning.
- `_MMVAD_SHORT` removes the dedicated `GraphicsVadFlags` union view. That may
  reflect graphics-VAD consolidation; it does not prove the underlying state or
  checks were removed.

## Removed / deprecated

- Win32k removes five analog-token/composition-surface calls and five desktop
  visual/content/input-sink calls. Remote textures and newer input/display
  plumbing may absorb parts of their roles, but the diff does not establish
  one-to-one replacements. **[anti-cheat] [vuln-research]** Trace compatibility
  thunks and compare authorization/lifetime semantics before calling the old
  functionality eliminated.
- Kernel verifier exports `VfFailDeviceNode`, `VfFailDriver`, and
  `VfFailSystemBIOS` disappear while much larger verifier/interposition symbol
  families arrive. This looks like interface refactoring, not reduced
  verification.
- Several 25H2 CI servicing gates—including the WinTcb PPL TOCTOU, policy
  deadlock, HVCI control-area synchronization, and cached-signing-level gates—are
  absent as named 26H1 symbols. Servicing-gate removal usually means integration
  or retirement of the conditional path; it does not demonstrate reversal.
- `__guard_retpoline_icall_handler` disappears while retpoline binary/relocation
  information types are added. Compiler and mitigation strategy changes can
  rename or redistribute these helpers, so runtime/control-flow inspection is
  required before making a protection claim.

## Research leads

1. Reverse the `NtManageWobTicket` information classes and build an access/QoS/
   priority matrix across processes, jobs, silos, impersonation, and teardown.
2. Enumerate every callback API covered by the new registration tree; test
   duplicate registration, failed removal, racing invocation, and driver unload.
3. Recover DIF/XDV wrapper dispatch and compare mediated versus direct calls for
   argument validation, caller identity, IRQL, exception, and fallback behavior.
4. Fuzz remote DirectComposition textures and GPU ring resizing across device
   loss, handle duplication, process death, and concurrent submission.
5. Exercise job UI-limit mutation and exception grants across nested jobs,
   AppContainer/session/desktop boundaries, and handle-right combinations.
6. Validate IOMMU fault attribution and callbacks under PASID reuse, surprise
   removal, reset, fault storms, and driver-proxy endpoint hot-swap.
7. Build a CI hotpatch policy matrix for target identity, sequence rollback,
   supplemental-policy refresh, Trusted Launch host SID, dev mode, and test
   signing.
8. Test ML-KEM/ML-DSA import/export and error paths with malformed lengths,
   decapsulation failures, provider-policy changes, and key-lifetime stress.
9. Trace the new pool manager's compaction/rebalancing and PFN buddy tags for
   stale metadata, cross-pool reuse, and concurrency bugs.

## Evidence and limitations

- “Added” means present in the selected KB5077179-derived binary database and
  absent from the selected serviced 25H2 file. It does not prove default
  enablement, low-privilege reachability, or exact first shipment in KB5077179.
- This is intentionally not BASE → BASE: every requested 26H1 BASE artifact was
  unavailable, so the first official cumulative update was selected. The old
  side also mixes revisions 5074 and 6584.
- Five 26H1 databases have blank embedded version metadata. Their tuple and
  official package identify KB5077179/build 28000.1575, but only kernel and ntdll
  expose usable file-version strings in the generated metadata.
- Native services are treated as new only with corroborating kernel/ntdll
  evidence. `NtCompleteConnectPort` is explicitly discounted; WOB is confirmed
  despite the diff script rendering the ntdll service under its `Zw*` alias.
- Symbol families may reflect compiler, linker, instrumentation, or module-boundary
  churn. The DIF/XDV and verifier counts are characterized as a subsystem rather
  than counted as independent features.
- Win32k and CI/CNG databases contain no reconstructed type changes in this
  comparison. Anonymous type IDs are hidden; only resolved parent/member changes
  support structure claims.
